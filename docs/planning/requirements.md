# CQC 프로젝트 요구사항

## 1. 문서 정보

| 항목 | 내용 |
|---|---|
| 프로젝트 | CQC |
| 목적 | 농산물 이미지의 품질 등급을 판정하고 선별 흐름과 검사 이력 관리를 자동화 |
| 현재 데이터 범위 | 사과 이미지 |
| MVP 품종 범위 | 부사(`fuji`)·양광(`yanggwang`) 2종 |
| 확장 한도 | 사과를 포함해 농산물 품목 최대 2종 |
| 프로젝트 기간 | 1개월 |
| 데이터베이스 | MySQL |
| 문서 상태 | 확정 정보 반영 완료. 미결정 항목은 TODO로 유지 |

## 2. 목표

시뮬레이터가 동일 사과의 다각도 이미지 그룹을 500ms 간격으로 자동 입력하면 AI가 부사·양광 품종과 특·상·보통 품질 등급, 각각의 확률과 신뢰도를 반환한다. 백엔드는 두 신뢰도와 Inference 응답 제한시간 정책에 따라 6개 정상 bin 또는 재검사 bin을 정하고, 검사 결과를 MySQL에 저장한다. 웹은 자동 검사 상태, 검사 이력과 통계·분석 정보를 제공한다.

## 3. 사용자

전체 MVP는 QC 이후 출품·경매·자동배차·배송 관제 시뮬레이션을 포함한다. 아래 QC 요구사항의 MySQL은 검사 이력 범위이며 물류 상태는 MongoDB로 분리한다. 물류 기능·수용 기준은 [물류 제품 범위](<../../cqc-logistics-platform/docs/01-product-scope.md>)를 따른다. 데모 역할 전환을 사용하고 실제 결제·차량 제어는 제외한다.

| 사용자 | 목적 | 주요 기능 |
|---|---|---|
| 선별 작업자 | 자동 검사된 사과의 품종·품질과 처리 위치 확인 | 품종·등급·신뢰도·선별 목적지 확인 |
| 품질 관리자 | 검사 현황과 품질 분포 분석 | 이력 검색, 통계·분석, 저신뢰 검사 확인 |
| 시스템 운영자 | 서비스와 모델 상태 확인 | 실행 상태, 모델 버전, 오류 확인 |

MVP는 농가 내부 대시보드로 가정하며 로그인과 권한 분리를 구현하지 않는다.

## 4. 범위

### 4.1 필수 범위

- 부사·양광 이미지 데이터 준비와 품종·품질 모델 학습
- 품종 2종과 특·상·보통 3등급 예측, 각 클래스 확률 제공
- 낮은 신뢰도 결과의 수동 검수 분기
- 등급별 선별 목적지 신호 생성
- MySQL 검사 이력 저장
- 웹 검사 결과, 이력, 통계·분석 화면
- 자동 테스트, 공통 실행 환경과 CI/CD 흐름

### 4.2 조건부 확장

- 두 번째 농산물 품목 지원
- 모델 주목 영역 시각화

조건부 기능은 사과 품종 2종의 통합 검증이 끝나고 일정과 데이터가 허용될 때만 진행한다.

### 4.3 범위 제외

- 설비 고장예지와 설비보전
- 농산물 3종 이상 동시 지원
- 당도, 맛, 내부 손상 판정
- 실제 유통 등급 인증과 가격 자동 결정
- 대규모 실시간 스트리밍
- 복잡한 자동 재학습과 무중단 배포
- 모바일 앱과 완전한 관리자 시스템
- 스마트폰 카메라 입력
- 사용자 이미지 파일 업로드
- 실제 산업용 카메라·PLC·물리 선별 장비 연동

## 8. 외부 인터페이스 요구사항

### 8.1 모델 인터페이스

- 입력: `inspection_id`, 다각도 `images[]`, 이미지별 `view_index`, `angle_direction`, `verticality_angle`, `horizontality_angle`을 포함한 multipart 요청. `group_no`와 정답 품종·품질은 모델 입력에서 제외
- 출력: `inspection_id`, 품종 예측과 `fuji`·`yanggwang` 확률 객체·신뢰도, 품질 예측과 `L`·`M`·`S` 확률 객체·신뢰도, 추론시간, 모델명·버전, 전처리 버전과 실제 사용 프레임 수
- 클래스 순서와 전처리 설정을 모델 산출물과 함께 제공
- 세부 형식은 조현재와 홍준희가 M1에서 확정

### 8.2 백엔드 API

- 검사 요청
- 단일 검사 결과 조회
- 검사 이력 조건 검색
- 통계·분석 집계 조회
- 서비스 상태 확인

경로, HTTP 메서드, 오류 코드와 응답 스키마는 홍준희가 별도 API 문서에서 확정한다.

### 8.3 MySQL

- 검사 이력과 처리 결과를 86,400건 상한의 순환 정책으로 저장
- 기간·품목·품종·등급·검수 여부별 조회와 집계를 지원
- 사용 모델·전처리 버전과 실제 적용한 품종·품질 confidence threshold를 검사 이력과 연결
- 검사·제어·저장 상태를 논리적으로 분리하고 DB 장애 중 저장하지 못한 이력의 유실을 허용
- 테이블, 컬럼, 타입, 키, 관계, 인덱스, 보존 정책과 마이그레이션은 홍준희가 별도 DB 설계 문서에서 확정

## 9. 완료 정의

MVP는 다음 조건을 모두 만족할 때 완료로 본다.

1. 사과 품종 2종의 데이터 분할과 모델 평가가 재현된다.
2. 정상 이미지에서 등급·신뢰도·선별 목적지를 반환한다.
3. 품종 또는 품질이 저신뢰인 사과 그룹을 재검사 bin으로 분리한다.
4. 검사 결과가 MySQL에 저장되고 웹에서 다시 조회된다.
5. 웹에서 검사 결과의 통계·분석 정보를 확인한다.
6. 오류 입력, 모델 누락과 DB 연결 실패를 구분해 처리한다.
7. 공통 실행 절차와 자동 테스트가 통합 환경에서 동작한다.
8. 발표 내용이 실제 구현과 측정 결과를 과장하지 않는다.
