# CQC 프로젝트 요구사항

## 1. 문서 정보

| 항목 | 내용 |
|---|---|
| 프로젝트 | CQC |
| 목적 | 농산물 이미지의 품질 등급을 판정하고 선별 흐름과 검사 이력 관리를 자동화 |
| 현재 데이터 범위 | 사과 이미지 |
| MVP 품종 범위 | 사과 품종 2종. 품종명은 데이터 확인 후 확정 |
| 확장 한도 | 사과를 포함해 농산물 품목 최대 2종 |
| 프로젝트 기간 | 1개월 |
| 데이터베이스 | MySQL |
| 문서 상태 | 확정 정보 반영 완료. 미결정 항목은 TODO로 유지 |

## 2. 목표

사용자가 농산물 이미지를 입력하면 AI가 특·상·보통 품질 등급과 신뢰도를 반환한다. 백엔드는 신뢰도 정책에 따라 등급별 선별 목적지 또는 수동 검수 대상을 정하고, 검사 결과를 MySQL에 저장한다. 웹은 현재 검사 결과, 검사 이력과 통계·분석 정보를 제공한다.

## 3. 사용자

| 사용자 | 목적 | 주요 기능 |
|---|---|---|
| 선별 작업자 | 개별 농산물의 품질과 처리 위치 확인 | 이미지 입력, 등급·신뢰도·선별 목적지 확인 |
| 품질 관리자 | 검사 현황과 품질 분포 분석 | 이력 검색, 통계·분석, 저신뢰 검사 확인 |
| 시스템 운영자 | 서비스와 모델 상태 확인 | 실행 상태, 모델 버전, 오류 확인 |

사용자 인증과 권한 분리는 현재 필수 범위로 확정하지 않았다.

## 4. 범위

### 4.1 필수 범위

- 사과 품종 2종의 이미지 데이터 준비와 품질 등급 모델 학습
- 특·상·보통 3등급 예측과 등급별 확률 제공
- 낮은 신뢰도 결과의 수동 검수 분기
- 등급별 선별 목적지 신호 생성
- MySQL 검사 이력 저장
- 웹 검사 결과, 이력, 통계·분석 화면
- 자동 테스트, 공통 실행 환경과 CI/CD 흐름

### 4.2 조건부 확장

- 두 번째 농산물 품목 지원
- 모델 주목 영역 시각화
- 물리 선별 장비 연동

조건부 기능은 사과 품종 2종의 통합 검증이 끝나고 일정과 데이터가 허용될 때만 진행한다.

### 4.3 범위 제외

- 설비 고장예지와 설비보전
- 농산물 3종 이상 동시 지원
- 당도, 맛, 내부 손상 판정
- 실제 유통 등급 인증과 가격 자동 결정
- 대규모 실시간 스트리밍
- 복잡한 자동 재학습과 무중단 배포
- 모바일 앱과 완전한 관리자 시스템

## 5. 기능 요구사항

| ID | 기능 | 요구사항 | 수용 기준 | 우선순위 | 담당 |
|---|---|---|---|---|---|
| FR-01 | 이미지 입력 | 사용자가 지원 형식의 농산물 이미지를 입력한다 | 정상 파일을 선택하면 검사 요청을 시작한다 | 필수 | 강성민·홍준희 |
| FR-02 | 입력 검증 | 형식, 크기, 이미지 해석 가능 여부를 검사한다 | 지원하지 않거나 손상된 파일은 추론 전에 오류로 처리한다 | 필수 | 홍준희 |
| FR-03 | 품질 추론 | 모델이 특·상·보통의 확률과 최종 등급을 반환한다 | 응답에 모델 버전, 예측 등급과 신뢰도가 포함된다 | 필수 | 조현재·홍준희 |
| FR-04 | 저신뢰 분기 | 신뢰도가 기준 미만이면 자동 선별을 보류한다 | 결과가 `REVIEW`로 기록되고 웹에 검수 대상으로 표시된다 | 필수 | 조현재·홍준희 |
| FR-05 | 선별 목적지 | 자동 판정 결과에 따라 목적지 신호를 만든다 | 특·상·보통 또는 REVIEW 중 하나가 생성된다 | 필수 | 홍준희 |
| FR-06 | 결과 표시 | 웹에서 품목·품종, 등급, 신뢰도와 처리 결과를 보여준다 | 정상·오류·저신뢰 상태가 서로 구분된다 | 필수 | 강성민 |
| FR-07 | 검사 이력 저장 | 검사 결과와 처리 정보를 MySQL에 저장한다 | 성공한 검사에 고유 ID가 생기고 재조회할 수 있다 | 필수 | 홍준희 |
| FR-08 | 이력 조회 | 웹에서 검사 기록을 조건별로 조회한다 | 기간, 품목, 품종, 등급과 검수 여부 기준을 지원한다 | 필수 | 강성민·홍준희 |
| FR-09 | 통계·분석 | 검사 결과의 집계와 분포를 웹에서 확인한다 | 기간·품목·품종·등급별 검사 수와 비율을 조회한다 | 필수 | 강성민·홍준희 |
| FR-10 | 모델 버전 기록 | 검사에 사용한 모델 버전을 남긴다 | 이력에서 모델 버전을 확인할 수 있다 | 필수 | 홍준희·홍유나 |
| FR-11 | 두 번째 품목 | 결정된 후보 품목을 선택해 검사한다 | M5에서 승인된 경우에만 구현한다 | 확장 | 전체 |

## 8. 외부 인터페이스 요구사항

### 8.1 모델 인터페이스

- 입력: 디코딩 가능한 이미지 또는 합의된 이미지 객체
- 출력: 품목, 필요 시 품종, 등급별 확률, 예측 등급, 신뢰도, 모델 버전
- 클래스 순서와 전처리 설정을 모델 산출물과 함께 제공
- 세부 형식은 조현재와 홍준희가 M1에서 확정

### 8.2 백엔드 API

- 검사 요청
- 단일 검사 결과 조회
- 검사 이력 조건 검색
- 통계·분석 집계 조회
- 서비스 상태 확인

경로, HTTP 메서드, 오류 코드와 응답 스키마는 홍준희가 별도 API 문서에서 확정한다.

### 8.3 MySQL

- 검사 이력과 처리 결과를 영구 저장
- 기간·품목·품종·등급·검수 여부별 조회와 집계를 지원
- 사용 모델 버전을 검사 이력과 연결
- 테이블, 컬럼, 타입, 키, 관계, 인덱스, 보존 정책과 마이그레이션은 홍준희가 별도 DB 설계 문서에서 확정

## 9. 완료 정의

MVP는 다음 조건을 모두 만족할 때 완료로 본다.

1. 사과 품종 2종의 데이터 분할과 모델 평가가 재현된다.
2. 정상 이미지에서 등급·신뢰도·선별 목적지를 반환한다.
3. 저신뢰 이미지를 REVIEW로 분리한다.
4. 검사 결과가 MySQL에 저장되고 웹에서 다시 조회된다.
5. 웹에서 검사 결과의 통계·분석 정보를 확인한다.
6. 오류 입력, 모델 누락과 DB 연결 실패를 구분해 처리한다.
7. 공통 실행 절차와 자동 테스트가 통합 환경에서 동작한다.
8. 발표 내용이 실제 구현과 측정 결과를 과장하지 않는다.
