# 프론트엔드 작업 종합 정리

기준일: 2026-09-29 · 작업 위치: `cqc-logistics-platform/apps/web` · 기준: [프로젝트 기획](../project-plan.md), [WBS](WBS.md)

## 1. 지금 어디까지 됐나

**품질 관제 화면과 관리 기능, HTTP API 호출부, 협업용 API 계약과 독립 참조 서버까지 구현했다. 09-30에 실제 Backend·DB·모델과 연결해 조회·통계·CSV·장애 이미지를 확인했다. 학원 서버 웹(3100)은 아직 브라우저 예시 모드라 실제 Simulator 제어 화면 연결과 배포는 남았다.**

FE-01~07은 화면과 클라이언트 구현을 갖췄고 참조 서버로 검증했다. FE-08은 로컬 화면·자동 시험까지, FE-09는 시연 순서·동결 체크리스트까지 준비했다. FE-10은 브라우저 자동 경매·배차 시연과 12장 그룹 관제를 추가했다(PR #21, dev `0b120fa`). 따라서 FE WBS 전체를 운영 완료로 표시하면 안 된다.

이번 정리는 구현 코드를 추가하지 않고 기존 작업과 문서를 현재 상태로 정리한 것이다. 이후 사용자 요청에 따라 WBS 작업 단위로 커밋·푸시한다.

## 2. 사용자 요청이 어떻게 반영됐나

| 요청 | 현재 반영 상태 |
|---|---|
| 첨부 초안 기반 수정 | 초안을 출발점으로 품질 화면을 관리자 관제에 맞게 재구성 |
| 지도 제외 | 이번 품질 관제 작업에서 지도 수정 제외 |
| 한 화면에 관제 정보 표시 | 처리 중 사과·상태/오류·최근 판정·처리 현황을 네 패널로 구성 |
| 전체 페이지 무스크롤 | 화면 전체 너비·높이를 고정하고 패널 및 관리 창 내부만 스크롤 |
| 확대·축소로 가독성 훼손 금지 | 전체 transform/zoom 축소 제거, 이미지가 남은 공간에 맞춰 조정 |
| 헤더·푸터·홍보 문구 삭제 | 품질 화면의 공통 헤더/푸터 제거, 불필요한 홍보 문구 제거 |
| N 아이콘 제거 | Next 개발 표시 `devIndicators: false` 적용 |
| 품질 화면에서 페이지 이동 불필요 | 품질 공통 헤더 숨김, 입찰/차량 메뉴에서 품질 탭 제거 |
| FE-01~03 문서 작성 | 개별 WBS 문서 작성 및 현재 API 구현 상태 반영 |
| 협업 선행을 기다리지 말고 구현 | FE API 클라이언트·proxy·OpenAPI·참조 서버를 먼저 구현 |

입찰·차량 화면은 기존 화면을 유지하며 공통 메뉴를 정리했다. 이번 작업으로 두 페이지의 실제 거래·배차 연동까지 완료했다고 주장하지 않는다.

## 4. 화면에서 할 수 있는 일

### 상시 관제

- 진행 중 사과 카드와 처리 상태 확인, 입력 정지·재개 및 동시 처리 수 변경.
- Simulator/Inference/Backend/MySQL 상태, 최근 오류, 마지막 저장 시점 확인.
- 최근 판정의 품종·품질·신뢰도·추론 시간·목적지·처리/제어/저장 상태 확인.
- 오늘 누적과 품종/등급 분포, 최근 처리 추이 및 기간 합계 확인.
- 통신 실패 시 마지막 결과와 끊김 경고 표시. API 오류를 예시 데이터로 자동 대체하지 않음.

### 필요할 때 여는 관리 창

- **검사 이력:** 날짜·품종·등급·bin·상태·오류·오판 의심 필터, 페이지 이동, 새로고침, CSV.
- **기간 통계:** 날짜별 집계, 분포·재검사 비율·평균 추론 시간·오판 의심 수, CSV.
- **시연 설정:** 추론 시간초과/추론 오류/DB 오류/명령 거부/제어 무응답, 전체 또는 다음 1건 적용.
- **장애 이미지:** 미리보기, 개별/전체 삭제 확인, 오판 의심 지정. 검사 이력은 유지.

저신뢰 판정은 품종·품질 집계에 포함하고 시간초과/추론 오류는 제외한다. 관리자 오판 의심 표시는 저신뢰와 별도다. 가상 당도는 비실측이며 누락값은 빈값으로 표시한다. CSV에는 이미지 원본·URL을 넣지 않는다.

## 5. 연결 구조와 실행 모드

```text
품질 관제 화면
  → Next 동일출처 /api/quality/* proxy
    → CQC_QUALITY_BACKEND_URL/v1/quality/*
      → 현재: 독립 참조 서버
      → 협업 후: 실제 Backend adapter → DB / Simulator / Inference
```

| 모드 | 데이터와 상태의 위치 | 새로고침/재시작 |
|---|---|---|
| demo | 브라우저 예시 상태 | 페이지 새로고침하면 초기화 |
| api + reference | 별도 Node 프로세스의 메모리 상태 | 페이지 새로고침해도 유지, 서버 재시작하면 초기화 |
| api + backend | 실제 Backend가 제공하는 상태 | 복구·보존 정책은 실제 서버 구현과 통합시험 필요 |

현재 참조 서버의 정적 이미지·추론 시간·서비스 상태는 예시다. 실제 모델 호출이나 MySQL 저장이 아니다. 참조 입력 1초 간격은 운영 목표 500ms 입력 또는 CPU 처리량 증거가 아니다.

참조 서버는 이력 2,000건·장애 이미지 100개·오류 50개·시계열 1,800개를 보관한다. snapshot은 최근 이력 200건·차트 30개와 기간 합계를 제공한다. CSV는 snapshot 200개가 아닌 보존된 필터 전체를 조회한다.

## 6. 협업을 위해 먼저 구현한 것

- [OpenAPI 계약](../contracts/quality-operations.openapi.json): snapshot, 이력/CSV, 통계/CSV, Simulator 제어, 오판 의심 수정, 장애 이미지 목록/삭제, preview.
- 제어 revision 충돌 시 409, 다음1건 원자적 소비, 완료 이미지 410, DB 장애 503 등 참조 응답.
- 오래된 요청 취소, 요청 시간 제한, 중복 제출 방지, 서버 성공 후 상태 반영.
- 삭제 확인 시 포착한 ID만 제거하여 새로 들어온 장애 이미지 보호.
- 허용 경로/메서드, 쓰기 요청 출처, 응답 형식, 이미지 경로를 검사하는 proxy/client.

**이 계약은 FE가 먼저 구현한 협업 기준이다. 팀 전체 승인이나 실제 Backend 구현 완료를 뜻하지 않는다.** 기존 검사 입력 `POST /v1/inspections`를 바꾸지 않고 관제용 adapter를 추가하는 방식이다.

| 담당 | 요청할 작업 | 연결 후 FE가 확인할 것 |
|---|---|---|
| Backend | 계약에 맞는 DB 이력·통계·CSV, 제어 adapter, 파일 만료/삭제 | 표시값·필터·통계·오류 응답 대조 |
| Simulator | 실제 입력 주기·bundle, 위치 저장/복구, NEXT 소비 | 정지/재개·병렬·다음1건 동작 |
| DM | 실제 모델 버전·품종/등급 신뢰도·추론 시간·제외값 | 단위·null·목적지 매핑 |
| MLOps | 배포 주소·접근 정책·볼륨·재시작·목표 CPU 측정 | 접속·복구·병렬 수·장시간 안정성 |
| 공동 | 실제 정상100개·5종 장애·복구·보존 수용시험 | FE-08/09 완료 및 동결 |

상세 전달 규칙과 실행법은 [관제 API 인계](협업공지/Frontend-관제-API-계약-인계.md)에 있다. 실제 다른 팀에게 메시지를 발송한 것은 아니다.

| 조작 | 정지/재개·병렬·장애·필터·CSV·미리보기·삭제 기록 | 주로 예시 화면 검증, 실제 서비스 통합 증거와 구분 |

자동 시험과 정적 검사·빌드는 2026-09-29 최신 dev에서 다시 실행했다. HTTP·브라우저·조작·지속 실행 항목은 이전 구현 작업의 기록이다. 실제 운영 완료율이나 모델 성능을 추정해서 적지 않았다.
