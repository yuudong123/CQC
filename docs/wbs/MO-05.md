# MO-05 Volume 및 비밀값 관리

## 1. 작업 개요

- WBS: MO-05
- 담당: 홍유나
- 상태: 부분 완료 (Volume·Secret·모델 패키지 연결 완료, 장애·로그 보존은 후속)
- 작업 목적:
  - MySQL 데이터가 컨테이너 재생성 이후에도 유지되도록 Volume 적용
  - MySQL 접속 정보를 코드에 직접 작성하지 않고 환경변수로 관리
  - Jenkins Credentials를 이용하여 CI/CD 환경에서도 비밀값을 안전하게 전달
  - 승인 모델 패키지를 버전·체크섬 단위로 읽기 전용 연결
  - Docker Compose 및 Jenkins Pipeline에서 정상적으로 MySQL이 기동되는지 검증

## 현재 상태 (2026-09-23)

MO-05의 MySQL Volume·환경변수·Jenkins Credentials 기반은 적용되어 있다. 이번 Compose 연결에서 `INFERENCE_MODEL_DIR`을 필수 입력으로 만들고 모델 패키지를 `/app/models/approved`에 읽기 전용으로 마운트했다. Inference 시작 시 `model.json`의 `checkpoint_sha256`과 `model.pt`를 비교하므로 체크섬이 맞지 않으면 컨테이너가 healthy가 되지 않는다.

## 2. 작업 배경

기존 `compose.yaml`에서는 MySQL 데이터 저장을 위한 별도의 Volume이 설정되어 있지 않았다.

이 경우 MySQL 컨테이너를 삭제하거나 재생성할 경우 컨테이너 내부에 저장된 데이터가 함께 삭제될 수 있다.

또한 초기에는 다음과 같이 MySQL 비밀번호에 기본값이 설정되어 있었다.

```yaml
MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:-cqc_local_root}
MYSQL_DATABASE: ${MYSQL_DATABASE:-cqc}
MYSQL_USER: ${MYSQL_USER:-cqc}
MYSQL_PASSWORD: ${MYSQL_PASSWORD:-cqc_local_password}
```

개발 환경에서는 편리하지만 실제 CI/CD 및 배포 환경에서는 비밀번호가 코드에 노출될 가능성이 있으므로,
MO-05에서는 환경변수 및 Jenkins Credentials를 이용하도록 변경하였다.

---

## 3. MySQL Volume 적용

MySQL 데이터를 Docker 컨테이너와 분리하여 저장하기 위해 Named Volume을 적용하였다.

### compose.yaml

```yaml
mysql:
  image: mysql:8.4
  restart: unless-stopped

  environment:
    MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
    MYSQL_DATABASE: ${MYSQL_DATABASE}
    MYSQL_USER: ${MYSQL_USER}
    MYSQL_PASSWORD: ${MYSQL_PASSWORD}

  volumes:
    - mysql_data:/var/lib/mysql
```

그리고 `compose.yaml` 최하단에 Volume을 선언하였다.

```yaml
volumes:
  mysql_data:
```

### 적용 이유

MySQL의 실제 데이터 저장 경로인 `/var/lib/mysql`을 Docker Named Volume과 연결하였다.

이를 통해 MySQL 컨테이너가 재생성되더라도 데이터 저장 공간은 컨테이너와 독립적으로 유지할 수 있다.

Jenkins 배포 과정에서도 `cqc-cicd_mysql_data` Volume이 정상적으로 생성되고 MySQL 컨테이너에 연결된 것을 확인하였다.

## 4. 환경변수 관리

MySQL 접속 정보를 `compose.yaml` 내부에 직접 작성하지 않고 외부 환경변수를 사용하도록 변경하였다.

```yaml
environment:
  MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
  MYSQL_DATABASE: ${MYSQL_DATABASE}
  MYSQL_USER: ${MYSQL_USER}
  MYSQL_PASSWORD: ${MYSQL_PASSWORD}
```

로컬 개발 환경에서는 `.env` 파일을 이용할 수 있도록 구성하였다.

예시:

```env
MYSQL_ROOT_PASSWORD=<root-password>
MYSQL_DATABASE=cqc
MYSQL_USER=cqc
MYSQL_PASSWORD=<mysql-password>
```

실제 `.env` 파일에는 비밀번호가 포함되기 때문에 Git 저장소에 업로드하지 않는다.

`.gitignore`에는 다음 설정을 유지하였다.

```gitignore
.env
```

공유가 필요한 환경변수 구조는 `.env.example`을 통해 제공하며, 실제 비밀번호는 포함하지 않는다.

## 5. Jenkins Credentials 연동

로컬 `.env` 파일은 `.gitignore`에 의해 GitHub에 업로드되지 않기 때문에 Jenkins Pipeline에서는 해당 값을 직접 사용할 수 없다.

따라서 Jenkins Credentials에 MySQL 비밀값을 별도로 등록하였다.

사용한 Credentials 구성:

- `cqc-mysql-creds`
  - MySQL 일반 사용자 계정 및 비밀번호
- `cqc-mysql-root-password`
  - MySQL root 비밀번호

Jenkinsfile에서는 실제 비밀번호를 직접 작성하지 않고 Credentials ID를 이용하여 환경변수를 주입하도록 구성하였다.

```groovy
environment {
    MYSQL_ROOT_PASSWORD = credentials('cqc-mysql-root-password')
    MYSQL_CREDS = credentials('cqc-mysql-creds')

    MYSQL_DATABASE = 'cqc'
    MYSQL_USER = "${MYSQL_CREDS_USR}"
    MYSQL_PASSWORD = "${MYSQL_CREDS_PSW}"
}
```

이를 통해 GitHub 저장소에는 실제 MySQL 비밀번호가 포함되지 않으면서 Jenkins Pipeline에서는 필요한 접속 정보를 사용할 수 있다.

## 6. Jenkins Pipeline 검증

환경변수 및 Volume 설정 이후 Jenkins Pipeline을 다시 실행하였다.

### Compose 설정 확인

```bash
docker-compose -f compose.yaml config
```

실행 결과 MySQL 설정에 다음 값이 정상적으로 전달되었다.

- `MYSQL_DATABASE`: `cqc`
- `MYSQL_USER`: `cqc`
- `MYSQL_PASSWORD`: Jenkins Credentials 값
- `MYSQL_ROOT_PASSWORD`: Jenkins Credentials 값

비밀번호 값은 Jenkins Console에서 `****` 형태로 마스킹되어 노출되지 않았다.

### Docker Compose 기동 결과

배포 과정에서 다음 순서로 서비스가 정상적으로 기동하였다.

```text
MySQL ─────┐
           ├→ Backend → Simulator
Inference ─┘          └→ Frontend
```

MySQL과 Inference가 먼저 Healthy 상태가 된 이후 Backend가 시작되었고,
Backend가 Healthy 상태가 된 이후 Frontend와 Simulator가 실행되었다.

## 10. 주의사항

- 실제 `.env` 파일은 GitHub에 업로드하지 않는다.
- Jenkins Credentials의 실제 비밀번호는 문서나 코드에 기록하지 않는다.
- `docker compose down`은 컨테이너만 제거하지만,
  `docker compose down -v`는 Volume까지 제거하므로 MySQL 데이터가 삭제될 수 있다.
- 운영환경에서는 개발용 비밀번호 대신 별도의 운영용 Credentials를 사용한다.
- 현재 Jenkins에서는 `MYSQL_CREDS_PSW`를 Groovy 문자열 보간으로 전달하는 방식에 대한 보안 경고가 발생하므로,
  추후 Jenkinsfile 개선 시 해당 경고를 제거하는 방향으로 수정한다.
