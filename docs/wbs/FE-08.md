# FE-08 반응형·지속 실행 검증

확인일: 2026-10-06. 상태: **완료**. 학원 서버 3100에서 반응형 7개 크기와 3시간 25분 연속 관제·탭 숨김 복귀를 확인했다. 계획한 8시간 대신 이 결과로 확정했다([결정 기록](../planning/decision-log.md) 10-06, #73).

## 브라우저 확인 (2026-09-28 기록)

| viewport | document scrollWidth/Height | 전체 transform | 패널 |
|---|---|---|---|
| 1920×1080 | 1920×1080 | none | 4개 모두 화면 안 |
| 1366×768 | 1366×768 | none | 4개 모두 화면 안 |
| 1024×768 | 1024×768 | none | 4개 모두 화면 안 |
| 390×844 | 390×844 | none | 4개 모두 화면 안, 내부 가로/세로 스크롤 |

1280×720 기본 화면도 document 크기 일치 확인. 관리 dialog는 자체 스크롤을 사용한다. 폰트 전체 축소 없음.

브라우저에서 정지·재개, 병렬4개, 다음1건 복수장애 적용, 미리보기, 품종오판 의심 지정, 개별 이미지 삭제, 삭제 후 이력 유지, 오판 필터 1건, CSV 결과 1건을 확인했다.

추가로 이력 448건에서 50건씩 2페이지 이동, 목록을 읽는 동안 행 고정, `기타` 지정 후 1건 필터를 확인했다. 다운로드된 CSV를 읽어 해당 검사 ID·`OTHER`·가상 당도·`brix_is_measured=false`와 이미지 필드 제외를 확인했다.

시작일이 종료일보다 늦으면 즉시 경고하고 CSV 버튼을 비활성화한다. 최종 1280×720 확인에서 전체 document 크기 일치, 4개 패널의 하단 704px 이내, transform 없음과 브라우저 오류·경고 로그 0건을 확인했다.

## 자동 시험 (2026-09-29 기록)

- `npm test`: 정상/저신뢰/timeout/추론오류, 정지 후 drain/재개, 다음1건 scope, DB 실패 중 선별 지속·저장 유실, 제어 거부/무응답, KST 자정, CSV escaping, health proxy를 검증한다.
- 2026-09-29 자동 시험 20개 통과, lint 및 프로덕션 빌드 통과. 저신뢰 결과는 정상 집계에 포함하되 관리자 오판 의심은 자동 등록하지 않는 조건도 검증했다.
- 8시간(28,800 tick) 가속 상태 전이에서 이력 2,000, 장애 이미지 metadata 100, 오류50, 시계열1,800, 진행중4 상한을 확인한다.
- 가속 시험은 브라우저를 실제 8시간 켠 heap 측정이 아니다. 배열 상한·상태 로직의 증거다.
- UI interval은 unmount cleanup. API polling은 이전 요청 완료 후 다음 요청을 예약하며 AbortController·서버 timeout·cleanup으로 중첩 요청과 이탈 후 갱신을 방지한다.

## 실제 Backend 연속 관제 (2026-09-30)

프로덕션 빌드(`next start`)를 1600×900으로 띄우고 집 PC Backend에 연결했다. 시연 묶음 40개를 순환하며 500ms 간격으로 3,600건을 넣고 15초마다 heap·DOM·오늘 건수를 기록했다. 원본: [연속 관제 기록](results/fe-long-run-real-backend-20260930.json).

| 항목 | 결과 |
|---|---|
| 실행 | 31.5분, 3,600건(정상 2,759·재검사 828·DB 중단 중 실패 13), 검사 응답 p95 263ms |
| JS heap | 5분 이후 중앙값 22~23MB·최대 30~32MB에서 유지, 25~30분 구간 최소 5.1MB까지 회수. 증가 추세 없음 |
| DOM 노드 | 1,968~2,074개, 2분 30초 이후 2,074개 고정 |
| 연결 상태 | 모든 표본 "서버 관제", 오늘 건수 191 → 3,636 연속 증가 |
| MySQL 50초 정지 | "서비스에 연결할 수 없습니다 · 마지막 수신 · 기존 화면 유지" 표시, 재시작 2초 뒤 경고 해제·집계 재개 |
| Inference 정지 | 장애 이미지 100장 상한 유지, 오래된 이미지부터 교체, 버튼 "장애 이미지 100장" |

DB 정지 중 시스템 상태 카드의 MySQL은 마지막 값("검사 이력 조회 성공")을 유지했다. 상단 경고로 끊김은 드러나지만 카드에도 마지막 수신 시각이 함께 보이므로 추가 수정은 하지 않았다. 미리보기 창은 다른 탭을 앞에 띄워도 `visibilityState`가 바뀌지 않아 탭 background/복귀는 확인하지 못했다.

## 학원 서버 연속 관제 (2026-10-06)

배포된 3100을 Edge 창(1600×980)으로 열어 두고 서버 Simulator가 넣는 실제 검사(2초 간격)를 그대로 관제했다. 서버 설정은 바꾸지 않았다. Playwright는 탭 visibility를 항상 visible로 고정해서 순수 CDP로 쟀다. 원본: [서버 연속 관제 기록](results/fe-long-run-server-20261006.json).

| 항목 | 결과 |
|---|---|
| 실행 | 09:15~12:40, 3시간 25분, 30초 표본 412개. 8시간 계획이었으나 측정 프로세스가 12:40에 세션과 함께 종료돼 이 구간으로 확정 |
| 강제 GC 뒤 heap (30분마다) | 8.1 → 6.8 → 7.1 → 8.5 → 8.7 → 7.5MB. 증가 추세 없음 |
| GC 전 heap | 시간대별 중앙값 14~18MB, 최대 31~33MB에서 반복 회수 |
| DOM 노드 · 이벤트 리스너 | 1,017~1,563개 · 340~953개 범위에서 오르내림, GC 시점 1,115~1,217개 · 373~421개로 일정 |
| 타이머·요청 중첩 | 활성 timeout 최대 1개, interval 1개, 동시 요청 최대 3개(snapshot + 검수 이미지) |
| 요청 | snapshot·검수 이미지 각 10,744건, 실패 59건 모두 재배포 구간. 중단(abort) 0건 |
| 브라우저 예외·콘솔 오류 | 0건 |
| 재배포 4회 | 09:32·09:49·10:42·10:51에 각 27~28초 끊김. 경고 `… · 마지막 수신 HH:MM:SS · 기존 화면 유지`가 뜨고 복구 뒤 새로고침 없이 사라짐. 웹이 새 빌드로 바뀌어도 열린 탭은 처음 코드로 계속 동작 |
| 탭 숨김 2회 (10분씩) | 숨긴 직후 조회가 1초 → 2초 간격, 5분이 지나면 브라우저 절전으로 1분에 한 번 수준. 복귀 1.0초 안에 경고 없이 최신 화면으로 돌아옴. 숨김 밖에서 hidden 0회 |

판정: 메모리 누수 없음, 타이머·요청이 쌓이지 않음, 재배포·탭 숨김에서 스스로 복구. WBS FE-08 완료 기준(대시보드 스크롤 없음, 관리 화면 스크롤 허용, 메모리 누수 점검)을 충족한다.

DB 중단·복구는 09-30 로컬 시험(위 절)으로, 검수 이미지 순환 삭제·만료는 QA-IMG-04·06(BE)과 QA-WEB-15로 확인한다([QA 목록](reference/ALL/qa-test-cases.md)).

추가 계약 시험: 응답 schema, 시점 고정 pagination/전체 CSV, 잘못된 입력 거부, revision 충돌, NEXT 한 건 소비, 오판 집계 중복 방지, preview 만료, 삭제 후 이력/신규 이미지 보존, DB 장애, 기간 통계, proxy 제한을 검증했다.
