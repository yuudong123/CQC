# 발표 데모 시나리오

## Seed 데이터

- 농가 2곳: 아산 사과농장, 충주 사과농장
- 구매처 1곳: 서울 마트(시드 낙찰 주문 기준)
- 차량 3대: 1톤 1대, 2톤 2대
- 기존 운행 노선 1개, 대기 차량 2대
- CQC 결과: 부사 특 500kg, 홍로 상 500kg

## 현재 화면 기준 시연

1. `/`에서 시연 농가·선별 라인 1, 초당 사과 그룹 1개, 동일 사과의 12장 참고 사진을 보여준다.
2. `자동 경매 시연`을 누르고 링크로 `/market`에 이동한다. 이동 중에도 검사 입력이 이어진다.
3. 같은 품종·등급·선별 목적지의 통과 4개가 모이면 시연 1kg 출품이 생성된다.
4. 시연 구매자 3명이 자동으로 입찰하고 약 12초 뒤 마감·주문 생성·자동배차가 이어진다. 최대 3건 이후 정지한다.
5. `/market`에서 구매자·관리자 역할 전환과 자동 시연 로그를 보여준다. 수동 입찰·마감도 기존대로 사용할 수 있다.
6. `/control`에서 추가 주문과 노선 경유지, 위치 polling을 확인한다.
7. 필요하면 차량 고장 버튼으로 대체배차와 알림을 시연한다.

브라우저 판정·당도·물량·가격·구매자는 시연값이고 실결제는 없다. 자동 경매는 이 탭이 열려 있는 동안만 진행한다. 새로고침 시 새 시연이며 기존 서버 데이터는 지우지 않는다. 상세 범위는 `docs/wbs/FE-10.md`에 기록했다.

현재 화면에는 별도 농가·배송·발표 전용 경로와 상·하차 완료 버튼을 두지 않는다. 상·하차 게이트와 배송 완료는 API 계약에 남겨 두고, 이번 화면 시연 범위에서는 관제 상태와 대체배차까지를 보여준다.

## 발표 핵심 문장

> CQC의 품질 데이터가 선별에서 끝나지 않고, 판매 의사결정과 차량 배차의 입력 데이터가 되도록 연결했습니다.

> 실제 자율주행 알고리즘을 만든 것이 아니라, 자율주행 화물망이 받아야 할 주문·경로·상하차·예외 관제 명령을 자동화했습니다.

## 실패 대비

- Google Maps 키 실패: 지도 영역 안내 fallback을 보여주고 좌표·차량 목록으로 시연 지속
- WebSocket 실패: 2초 Polling으로 최고가 갱신
- 경로 API 실패: 좌표 간 직선거리와 고정 속도로 ETA 계산
- 시연 데이터 꼬임: seed reset 버튼으로 초기 상태 복구
