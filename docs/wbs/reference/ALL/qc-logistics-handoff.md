# QC 결과와 물류 연결 기준

2026-09-23. project-plan 3.7절의 구현용 연결 기준. 현재 물류 API는 데모 CQC 결과를 받을 수 있으나 실제 QC Backend 전달은 미연결이다.

## 필드 대응

| QC 결과 | 물류 입력 | 처리 기준 |
|---|---|---|
| inspection_id | cqcId | 동일 식별자를 유지 |
| crop_type | crop | 현재 apple |
| predicted_cultivar | variety | fuji / yanggwang |
| predicted_grade | qualityGrade | L → SPECIAL, M → PREMIUM, S → STANDARD |
| cultivar_confidence, quality_confidence | confidence | 단일 필드는 두 값의 최솟값 사용. 원래 두 값은 QC 이력에 보존 |
| 농가 입력 | farmId | 추론값으로 생성하지 않음 |
| 출품 물량 | quantityKg | 농가 입력. 이미지 장수나 사과 그룹 수로 kg를 추정하지 않음 |
| 농가 위치 | origin | GeoJSON Point, 경도·위도 순서 |

위 변환은 연결 계층의 구현 기준이며 기존 API에 이미 구현된 것으로 표시하지 않는다. 출품 물량이 여러 검사를 묶는 경우에는 대표 검사 선정·묶음 식별 규칙을 별도로 정해야 하며, 단일 검사 결과를 전체 물량의 검증 결과로 일반화하지 않는다.

## 전달과 실패 처리

1. QC 검사·제어·저장 결과를 확정한다.
2. 정상 판정 또는 검수 해제 결과에 농가·물량·위치를 붙여 출품 초안을 만든다.
3. 물류 저장 실패가 이미 실행한 선별 명령을 되돌리지 않도록 한다.
4. 같은 cqcId 재전송 시 중복 출품이 생기지 않는지 통합 테스트한다. 현재의 중복 처리 동작은 연결 전 확인한다.
5. 가상 당도는 실측값이 아니며 가격·품질 확정 근거로 사용하지 않는다. 기존 물류 스키마에는 아직 당도 필드가 없다.

## 완료 판단

- 실제 QC 응답 1건으로 수동 보완 정보를 포함한 출품 초안을 생성한다.
- 저신뢰·timeout·오류 결과는 자동 출품에서 제외하고 검수 대기로 남긴다.
- 품질 코드 3종과 품종 2종의 매핑, ID 유지, 중복·물류 장애를 검증한다.
- 실제 QC 서버·DB 연결 전에는 mock 독립시험으로 명시한다.
