# FE-10 자동 경매 시연과 사과 그룹 관제 개선

## 구현 범위

- `/` 제목 옆에 단일 시연 농가·선별 라인 1을 표시한다. 다중 농가·라인 선택 및 실제 설비 식별 API는 구현하지 않는다.
- 브라우저 예시는 500ms마다 사과 **한 그룹**을 투입한다. 한 그룹의 12장을 동시에 보여준다. 병렬 설정을 늘려도 투입 속도는 초당 2개이다.
- 원본 데이터의 동일 `source_group_id`에서 완전한 12장 묶음 6개를 선택하여 WebP 72장으로 축소했다. 중복 이미지로 12장을 채우지 않는다.
- 사진은 참고 이미지이고 화면의 검사값은 예시 판정이다. 실제 추론을 돌려 만든 결과가 아니다.
- 공통 레이아웃이 검사 상태를 유지하여 품질 검사·입찰·차량 관제로 이동해도 입력을 계속한다. 링크 이동을 사용하며 새로고침은 상태를 초기화한다.
- `자동 경매 시연` 또는 입찰 시장의 `자동 시연 시작` 한 번으로 진행한다. 기본은 자동 경매 꺼짐이다.
- 시작 이후의 저장·통과·정상 선별 결과만 품종/등급/선별 목적지별로 4개씩 묶는다. 검수·오류·오판 의심·제어 실패는 제외한다.
- 시연용 4개를 1kg으로 환산하고 최저가 5,000원, 픽업 좌표 `[127.004, 36.789]`, 시연 농가 ID를 사용한다. 실측 중량·실제 농가 설정·시장 시세가 아니다.
- 기존 물류 API에 `CQC 결과 등록 → 출품 → 공개 → 시연 구매자 3회 입찰 → 약 12초 뒤 마감 → 주문 배차` 순으로 요청한다. API 확인 주기 때문에 마감 시각에 약간의 지연이 있다.
- 자동 출품을 선택하여 최고가와 입찰자 변화를 보여준다. 서버의 기존 시드 경매에는 자동 입찰하지 않는다.
- 실행당 최대 3건 완료 후 정지한다. 입찰 시장 상단에 진행·오류·완료 이력을 남긴다.
- 중간에 오류가 나면 정지하며 재개 시 서버 목록과 주문 상태를 조회해 완료 단계를 복구한다. 일시정지 중에도 서버 경매 상태는 남는다.

## 연동 경계

- 당도 구간은 검사 결과의 `bin`을 사용한다. 새 당도 경계를 경매 코드에 별도로 하드코딩하지 않는다.
- `rawPayload`에 시연 출처, 검사 ID 목록, 모델 버전, 가상 당도 및 비실측 표시를 보낸다.
- API 모드의 실제 Simulator 투입 간격이나 이미지 응답 계약은 바꾸지 않는다. 현재 API가 제공하는 대표 사진만 표시하며 12장 API 연동은 후속 계약이 필요하다.
- 자동 경매 실행자는 현재 브라우저 탭이다. 창을 닫거나 새로고침하면 멈춘다. 새 시연은 새 식별자로 출품하며 이전 서버 데이터는 삭제하지 않는다. 여러 탭에서 동시에 시작하지 않는다.
- 실서비스용 중복 방지·권한·농가별 설정·백그라운드 출품은 Backend에서 관리할 후속 범위다. 현재는 단일 탭에서 응답 유실 재시도를 처리하는 시연이다.
- 가용 차량이 없으면 완료로 표시하지 않고 오류·재개 상태로 남긴다. 배송 완료와 상하차 인증은 자동 처리하지 않는다.
- Jenkins 설정, 지도 키, Backend/ML/Data 브랜치 작업물은 변경하지 않는다.

## 검증

- 최신 dev 통합 후 웹 자동 테스트: 31개 통과. 분류 누적·중복 제외·500ms 집계·사진 72장 존재·출품/입찰/낙찰/배차 재시도·가용 차량 오류 포함.
- 웹 정적 검사 오류 0건 및 운영 빌드 통과. dev에서 추가된 계약 테스트에 미사용 변수 경고 5건이 남아 있다.
- 로컬 물류 API 메모리 저장소와 운영 빌드 웹을 연결해 버튼 한 번으로 출품 3건의 자동 입찰·낙찰·배차 완료를 확인했다.
- 서버 Docker/Jenkins 배포 성공을 확인한 결과는 아니다. `feat/front → dev` PR 병합 후 별도 배포 확인이 필요하다.

## 2026-09-30 물류 시연용 가상 동작

물류를 MVP에 넣을지 결정하기 전 시연(10-01)을 위해, 입찰 시장·차량 관제·자동 경매 시연을 **물류 API·MongoDB 없이 브라우저 안에서만** 동작하게 바꿨다.

- `src/lib/logistics-fake.ts`가 `apps/api`의 `MemoryStore`와 라우트 응답·오류 문구를 그대로 옮긴 가상 물류 서버다. 발표 초기 상태(출품 2건·차량 CQC-01~03·배차 1건)도 같다.
- 상태는 같은 브라우저의 `localStorage`에 두어 탭을 나눠도 공유한다. `발표 상태 초기화`로 처음 상태로 돌아간다.
- 상차·하차 확인 화면이 없으므로, 차량이 경유지에 도착하고 3초가 지나면 작업자가 확인한 것으로 처리한다(실제 API의 load-complete·unload-complete와 같은 전이).
- 화면의 연결 표시는 "● 시연용 가상 물류"로 나온다. 입찰 시장의 경매 WebSocket은 가상 모드에서 열지 않는다.
- 기본값이 가상 모드다. 실제 물류 API를 쓰려면 웹 빌드 시 `NEXT_PUBLIC_LOGISTICS_MODE=live`를 준다. Compose·Jenkins는 바꾸지 않았다.
- 확인: `tests/logistics-fake.test.cjs` 5개(시드, 출품→배차, 이동·도착·고장·초기화, 자동 시연 6단계, fetch 대체)와 브라우저에서 입찰·자동 시연(30초에 2/3건 배차)·이동·고장·초기화, 외부 요청 0건.
