# 모델·추론 연동 계약 공지

> 디스코드 공유용. 데이터·모델 파트 구현 기준이며 백엔드·프론트·MLOps는 아래 계약에 맞춰 연동한다.

## 1. 확정 사항

- 검사 단위는 이미지 1장이 아니라 **동일 사과의 다각도 이미지 그룹 1개**다.
- MVP 품목은 `apple`이다.
- 품종 클래스 코드와 순서는 `fuji`, `yanggwang`으로 고정한다.
- 품질 클래스 코드와 순서는 `L`, `M`, `S`로 고정한다.
- 화면 표시명은 `fuji=부사`, `yanggwang=양광`, `L=특`, `M=상`, `S=보통`이다.
- inference는 품종·품질 예측만 담당한다. bin 결정, 저신뢰 판정, 재검사, DB 저장은 백엔드 책임이다.
- 최종 Test는 모델·입력 장수·임계값 선정에 사용하지 않고, 최종 모델 승인 후 1회만 실행한다.

## 2. 추론 요청 계약

### Endpoint

`POST /v1/predict`

### Content-Type

`multipart/form-data`

### 파일 필드

- 필드명: `images`
- 지원 형식: `image/png`, `image/jpeg`
- Base64 JSON 전송 금지
- 최소 1장 이상
- 기본 시연에서는 데이터 담당이 사전 구성한 `realtime-apple-arrival-demo/index.json`의 12장 묶음을 Simulator가 `request.json` 순서대로 읽는다. Backend는 이미지와 metadata를 변경 없이 전달한다. `angle_direction → horizontality_angle → verticality_angle → sample_id` 정렬·균등 선정은 묶음 생성 단계의 기준이다.
- 모델 목표 입력 12장보다 적은 경우 inference가 마스크 패딩한다.
- 12장을 초과하면 HTTP 413으로 거부한다.
- 정답 품종·품질과 `group_no`는 모델 특징으로 전달하지 않는다.

요청 제한은 PNG/JPEG 이미지 1~12개와 multipart 이미지 합계 24MiB로 고정한다.

## 3. 추론 응답 계약

성공 시 HTTP `200`과 아래 JSON을 반환한다.

```json
{
  "crop_type": "apple",
  "predicted_cultivar": "fuji",
  "cultivar_confidence": 0.94,
  "cultivar_probabilities": {
    "fuji": 0.94,
    "yanggwang": 0.06
  },
  "predicted_grade": "L",
  "quality_confidence": 0.88,
  "quality_probabilities": {
    "L": 0.88,
    "M": 0.09,
    "S": 0.03
  },
  "inference_time_ms": 143.2,
  "model_name": "mobilenet_v3_small_multiview",
  "model_version": "TODO_AFTER_APPROVAL",
  "preprocessing_version": "rgb-resize-imagenet-v1"
}
```

규칙:

- 확률 키를 번역명으로 바꾸거나 순서를 재정의하지 않는다.
- `cultivar_confidence`는 선택된 품종의 최대 확률이다.
- `quality_confidence`는 선택된 품질의 최대 확률이다.
- `inference_time_ms`는 이미지 전송·백엔드·DB 시간이 아닌 모델 순전파 시간이다.
- 모델 버전은 검사 이력에 반드시 저장한다.

## 4. 오류와 상태 계약

| 상황 | HTTP | 처리 |
|---|---:|---|
| 이미지 없음·손상·디코딩 실패 | 422 | 백엔드는 시스템 오류 검사로 기록하고 재검사 처리 |
| PNG/JPEG 외 형식 | 415 | 백엔드는 시스템 오류 검사로 기록하고 재검사 처리 |
| 모델 파일 누락·체크섬 불일치 | 서비스 시작 실패 | MLOps 상태 실패, backend는 inference 연결 실패 처리 |
| 예상하지 못한 추론 오류 | 500 | backend는 inference 오류 처리 |
| backend 제한시간 500ms 초과 | backend timeout | 늦은 결과는 진단용이며 확정 bin을 변경하지 않음 |

상태 확인은 `GET /health`를 사용한다. 정상 상태는 `status=ready`, `model_loaded=true`, 모델명·버전·장치·입력 장수를 포함한다.

## 5. 파트별 반영 사항

### 백엔드

- multipart의 반복 필드명은 `images`로 고정한다.
- 응답 확률과 예측값을 재계산하거나 클래스 순서를 바꾸지 않는다.
- 두 신뢰도 임계값, bin, 재검사, timeout, DB 저장을 담당한다.
- inference 연결 실패·HTTP 오류·500ms 초과를 정상 예측으로 저장하지 않는다.
- 확정된 이미지 1~12개·합계 24MiB 제한을 요청 검증과 배포 설정에 동일하게 적용한다.

### 프론트엔드

- 품종·품질 코드의 한글 표시는 화면에서만 매핑한다.
- 신뢰도는 품종과 품질을 별도로 표시한다.
- 모델 버전과 추론시간을 관리자 이력에서 확인할 수 있게 한다.
- inference를 직접 호출하지 않고 backend API만 호출한다.

### MLOps

- 배포 슬롯 `/app/models/approved`를 inference 컨테이너에 읽기 전용으로 마운트한다. 경로명과 모델의 품질 승인 상태는 구분한다.
- `model.pt`와 `model.json`을 한 버전 단위로 배포한다.
- 서비스 시작 전 SHA-256 검증을 통과해야 한다.
- healthcheck는 `/health`를 사용하고 inference 준비 전 backend 정상 상태로 간주하지 않는다.
- CPU용 PyTorch 이미지와 모델 볼륨 경로를 Compose에 고정한다.

## 6. 최초 공지 당시 미확정이었던 값

> 아래 목록은 최초 공지 시점의 기록이며, 현재 계약은 8절의 확정 전달값을 따른다.

- 최종 모델 구조: `joint` 또는 `separate`
- 최종 입력 장수: 4·8·12·16·40장 중 하나
- 요청당 최대 파일 수·전체 바이트
- 품종 신뢰도 임계값
- 품질 신뢰도 임계값
- 승인 모델 버전·체크포인트 SHA-256
- i7-4790 CPU 평균·최대·p95와 500ms 충족 여부

위 값 외의 클래스 코드, 필드명, 응답 책임 분리는 확정 사항으로 취급한다.

## 8. 최초 모델의 확정 전달값 (버전 이력)

- 모델 구조·입력: `separate`, 대표 이미지 12장
- 요청 형식: `multipart/form-data`, 반복 필드명 `images`
- 요청 제한: 이미지 1~12개, 전체 24MiB
- 품종 신뢰도 기준: `0.50`
- 품질 신뢰도 기준: `0.50`
- 두 신뢰도가 모두 기준 이상일 때만 정상 bin 후보로 처리
- 운영 기본 동시 처리 수: `1`
- 모델 버전: `cqc-apple-separate12-v1.0.0`

위 버전과 아래 9절 SHA는 최초 모델의 기록이다. 이후 v2 후보와 CPU 측정은 10절을 따른다. 다른 버전의 SHA와 성능을 섞어 기록하지 않는다.

## 9. 최종 평가 공지

- 체크포인트 SHA-256: `7c2d68a9f56f6e00555bb5e79db5bd0881caa6e742ae5d04469525a89e8183a2`
- 최종 Test 27그룹 1회 평가 완료
- 품종 Macro F1: `1.0000`
- 품질 Macro F1: `0.7778`
- 사전 승인 기준: 두 과제 각각 `0.90` 이상
- 판정: **품질 기준 미달, 승인·운영 배포 금지**

HTTP 계약과 모델 패키지 로딩은 정상이다. 백엔드·프론트·MLOps는 기능 통합에 이 패키지를 사용할 수 있지만, 발표나 문서에서 최종 승인 모델 또는 운영 성능 달성으로 표현하면 안 된다. 개선판은 신규 독립 holdout을 확보한 뒤 별도 버전으로 검증해야 한다.

## 10. 2026-09-29 dev 기준 후속 상태

- PR #18로 FE의 관제 API 클라이언트·참조 서버가 dev에 반영됐다. [관제 API 인계](Frontend-관제-API-계약-인계.md)를 기준으로 실제 Backend 응답과 두 신뢰도·모델 버전·추론 시간을 대조한다.
- i7-4790 측정은 미실시가 아니다. [MO-06](../MO-06.md)과 [Compose HTTP 원본](../reference/DM/results/i7-4790-compose-backend-inference-http-20260923.json)에 `cqc-apple-separate12-focal-v2-candidate`의 합성 224×224 JPEG 12장 시험이 있다. Backend→Inference HTTP p95는 약 205.76ms다.
- 이 결과는 실제 시연 사진·DB 저장·Simulator·FE까지 포함한 수용시험이 아니다. 실제 사진의 전송·디코딩·저장 비용과 병렬 수는 추가 검증한다.
- 8~9절의 v1 버전·SHA·평가 기록과 v2 후보의 시험 기록을 구분한다. 배포 담당은 선택한 package의 model.json·model.pt SHA와 health 응답 버전을 함께 확인한다.
- 기존 최종 Test를 다시 사용한 개선 결과를 신규 독립 평가로 표현하지 않는다. 품질 승인과 기능 통합을 구분하고 신규 독립 holdout 확보를 협의한다.
## 11. 2026-09-30 추론 서버 변경 (본문 계약 불변)

- `/v1/predict` 응답 JSON은 그대로다. 단계별 시간을 응답 헤더 `Server-Timing: decode;dur=…, model;dur=…, total;dur=…`(ms)로 추가했다. Backend는 필요하면 헤더를 읽어 지연 원인(사진 해제·모델)을 기록할 수 있다.
- `/health`에 선택 필드 `approval_status`, `threshold_status`, `checkpoint_sha256`, `quality_temperature`, `cultivar_temperature`, `decode_workers`를 추가했다. 배포 담당은 `checkpoint_sha256`과 `model_version`으로 배포 버전을 확인한다.
- 추론 중에도 `/health`가 응답한다(추론을 스레드 풀에서 실행).
- 사진 해제 병렬 수: 실행 인자 `--decode-workers` 또는 환경변수 `INFERENCE_DECODE_WORKERS`(기본 0=CPU 수 자동). Compose의 `OMP_NUM_THREADS=1`과 별개다.
- 신뢰도 보정: 보정된 패키지는 manifest의 temperature를 적용해 **같은 예측 등급에 다른 신뢰도**를 낸다. 보정 패키지는 새 `model_version`을 가지므로 이력의 버전으로 구분한다. 임계값은 보정 결과를 보고 다시 정해 Backend `CULTIVAR_CONFIDENCE_THRESHOLD`·`QUALITY_CONFIDENCE_THRESHOLD`에 반영한다(DM-08 문서 2026-09-30 절).
- 실제 시연 사진(1000×1000 PNG 12장, 평균 13.8MiB)은 합성 224 JPEG보다 해제 비용이 크다. 클라우드 2 vCPU 기준 서버 전체 p95는 순차 해제 410ms, 병렬 해제 261ms였다. i7-4790에서 실제 시연 사진으로 재측정한다(`scripts/evaluate_demo_bundles.py --mode http`).
