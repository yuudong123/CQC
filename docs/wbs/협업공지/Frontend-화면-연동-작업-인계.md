# Frontend 화면 및 파트별 연동 작업 인계

기준일: 2026-09-28. 최신 `dev`의 `1de97e3`에서 분기한 `feat/front` 작업이다. 화면은 `cqc-logistics-platform/apps/web`의 Next.js 앱 하나로 구성한다. 새 페이지보다 현재 세 화면의 실제 데이터 연결을 우선한다.

## 현재 제공하는 화면

| 경로 | 제공 기능 | 데이터 상태 |
|---|---|---|
| `/` | 검수 대상 선택, 같은 사과의 5개 참고 사진 전환, 최근 판정, 가상 당도, 정상 12-bin 및 재검사함, 품질 요약 | 예시 데이터. 실제 QC 조회·검수 확정 API 미연결 |
| `/market` | 출품 조회, 구매자/관리자 전환, 입찰, 마감, WebSocket 및 재조회 | 기존 물류 API 호출. 출품 이미지는 품종·등급별 참고 이미지 |
| `/control` | 차량 선택, 활성 경로 지도, 이동·고장·대체배차, 데모 초기화 | 기존 물류 API 호출. 실제 자율주행 차량 제어 아님 |

품질 화면의 가상 당도는 UI 예시 숫자다. `demo-virtual-brix.csv` 값과 연결한 상태가 아니다. 품질 불합격 표시는 예시 상태이며 실제 Backend 오류·검수 상태 매핑은 아래 계약 협의 후 교체한다. 역할 전환은 시연 UI이며 인증 기능이 아니다.

## Backend 담당 요청

1. **QC 조회 계약 제공:** 검사 생성 `POST /v1/inspections` 외에 최근 검사 목록·상세·검수 대상·오늘 통계·시스템 상태를 제공할 조회 API를 확정한다. 경로를 임의로 만들지 말고 OpenAPI와 응답 예시를 함께 전달한다.
2. **화면 필드:** `inspection_id`, KST 발생 시각, 품종·외관 등급, 각각의 confidence, 검수 사유·오류 코드, `virtual_brix`, 출처, `brix_is_measured=false`, `sweetness_band`, `target_bin_code`, 검사·제어·저장 상태가 필요하다. 단일 신뢰도를 표시할 경우 두 confidence의 최솟값 사용 여부를 확정한다.
3. **12-bin 집계:** 품종×외관×당도 구간의 정상 12개와 `TEST_REINSPECTION_BIN`을 반환한다. 12.0은 이상 구간이다. 물량 건수와 실제 적재량·용량은 구분하고 미측정 값을 0으로 채우지 않는다. 실제 시연 요청의 가상 당도 누락은 재검사로 처리한다.
4. **DB·Simulator:** 당도 구간을 포함하는 새 migration/seed, 검사 결과 Repository, 500ms 입력·시작/정지·위치 복구를 구현한다. 정상 사진 영구 보존 없이 사진 표시를 지원할 수 있는 임시 수명·접근 계약을 확정한다. 현재 FE 참고 사진을 실제 검사 사진으로 사용하지 않는다.
5. **검수 확정:** 채택할 검수 동작과 기록·재처리 API를 정한다. 현재 화면은 버튼을 통한 허위 완료 처리를 하지 않는다. CSV·이력 필터·장애 토글을 발표에 포함한다면 같은 화면의 확장 범위로 FE와 계약한다.
6. **QC → 물류:** 정상/검수 해제 검사에 농가·kg·위치를 붙여 출품한다. 저신뢰·timeout 제외, 중복 방지, 물류 장애 중 QC 선별 지속을 검증한다. 상세 기준은 [QC 물류 연결](../reference/ALL/qc-logistics-handoff.md)을 따른다.

## 데이터·모델 담당 요청

- 배포용 v2 모델 버전·SHA-256·클래스 매핑·confidence 기준을 MO/BE와 동일하게 맞춘다. v3는 현재 배차 모델이 아니다.
- `realtime-apple-arrival-demo/index.json`, 묶음별 `request.json`, 사진 약 13.7GB, `demo-virtual-brix.csv`의 전달 경로와 생성 버전을 제공한다. 기본 869묶음, 잔여 partial 제외, 반복 묶음을 새 사과로 계산하지 않는 규칙을 유지한다.
- 정상 12-bin 중 기본 자료에서 비어 있는 조합 2개는 0건으로 표시한다. 모든 bin이 채워졌다고 꾸미지 않는다.
- 참고 사진 출처는 `public/apples/provenance.json`에 있다. 추론 정답·원본 group_no를 모델 입력으로 보내지 않는다.

## MLOps 담당 요청

- FE는 현재 `logistics-web`이 빌드하는 이 앱 하나에 품질 화면까지 포함되어 있다. QC `frontend` placeholder를 어떻게 정리할지 결정하고 웹 앱을 중복 배포하지 않는다.
- Docker 빌드 인자 `NEXT_PUBLIC_API_URL`은 브라우저에서 접근 가능한 물류 API 주소다. 컨테이너 내부 DNS와 브라우저의 `localhost`를 넣지 않는다. QC API 연결 시 별도 QC 주소 또는 reverse proxy 경로를 BE/FE와 확정한다.
- Google Maps 키는 기존 빌드 인자로 공급하고 실제 웹 주소의 도메인 제한과 지도 로딩을 확인한다. 키를 문서·소스에 기록하지 않는다.
- QC·물류 API CORS, MySQL migration/13-bin seed, 모델 포함 이미지, Simulator 사진/CSV volume, healthcheck 및 Jenkins `dev` 배포를 맞춘다.
- 실제 서버에서 세 페이지 이동, API 장애 안내, 입찰→낙찰→배차→고장 대체, 재시작 상태 복구를 확인한다. 합성 입력 CPU 측정과 실제 12장 입력 전체 서비스 성능을 구분한다.

## FE 후속 연결 및 완료 기준

1. BE OpenAPI 확정 후 품질 예시 데이터를 조회 어댑터로 교체한다. 품질 화면은 1초 갱신, 물류 화면은 기존 조회/WebSocket 동작을 유지한다.
2. 빈 목록·연결 실패·지연·검수·오류 상태를 실제 응답과 매핑한다. 정상 상태에서도 샘플 사진을 실물 사진처럼 표시하지 않는다.
3. QC 응답이 화면과 12-bin 집계에 표시되고, 정상 검사 출품이 시장에 등장하며 낙찰 후 관제 경로까지 이어져야 전체 통합 완료다.
4. 1920×1080·1366×768 및 작은 화면에서 텍스트 가독성·선택·스크롤 동작을 확인한다. 현재 품질 화면은 콘솔 전체를 화면 크기에 맞춰 축소하는 방식이라 작은 화면 사용성은 별도 확인이 필요하다.
5. 로컬 `npm run lint`, `npm run build`와 실제 서버 브라우저 시험을 구분해 기록한다. 현재 빌드 통과만으로 배포 완료라고 표시하지 않는다.
