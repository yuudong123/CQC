## 1. 목표와 판단 원칙

실제 Inference·MySQL로 정상 100건 연속 저장·통계 일치, 장애별 상태·오류·재검사 bin·통계 제외, 이력 필터·CSV UTF-8 BOM·KST ms를 검증하고 ALL-04에 증거를 남긴다. 실제 데이터량에서 `completed_at` 정렬·기간 조회 성능도 확인한다(BE-05 후속 범위).

사용자의 현재 지시, 최신 확정 계약, 최신 Issue 협의, 코드·테스트, 과거 완료 기록 순으로 판단한다. 문서의 시험 기대값은 현재 구현의 결함까지 승인한다는 뜻이 아니다. 계약 불일치는 목표 기대값과 현재 동작을 나란히 기록한다. 정량 후보는 사용자가 승인하기 전 PASS/FAIL 기준으로 사용하지 않는다.

1/4에서는 시험 설계만 했다. 이후 사용자 지시로 실행한 2/4 로컬·격리 결과는 [결과표 §9](BE-10-results.md#9-be-10-24-로컬격리-통합-검증)에 별도 기준선으로 기록한다. 아래 두 시험표는 명세이며, 실행 상태는 결과표를 따른다. 3/4~4/4는 아직 미실행이다.

### 2.3 Compose·배포

`compose.yaml`은 MySQL 8.4, 실제 Inference·Backend·독립 Simulator·logistics-web과 물류 API/DB를 포함한다. QC UI는 logistics-web(기본 3100)에서 `CQC_QUALITY_MODE=api`, `CQC_QUALITY_BACKEND_URL=http://backend:8000`으로 연결된다. 물류 기능 수용은 BE-10 범위 밖이다.

- Inference: CPU, 모델 `/app/models/approved`, OMP/MKL thread 기본 1. 실제 image·thread·ready 상태는 통합환경 확인 필요.
- Backend: `alembic upgrade head` 뒤 기동, 실제 HTTP Inference 기본, MySQL·Inference health 의존, connect 기본 200ms.
- Simulator: 기본 2000ms, 공개 선택 1000/2000/3000ms, concurrency 1/2/4; 마지막 위치 RW volume, Dataset RO volume, Backend와 내부 인증 token 일치 필요. secret 값을 문서·증거에 남기지 않는다.
- 이미지 volume: `/data/fault-images`의 기존 root와 그 아래 `low-confidence` root. 독립 인스턴스 기본 한도 100/200. override와 쓰기 권한은 통합환경 확인 필요.
- DB·위치·서비스 로그 volume과 `unless-stopped` 유지. Backend worker 수 확인 필요(보존 건수 공유는 단일 프로세스 구현).
- Jenkins: Python Test → Web Test → Docker Build / Basic Check → Deploy → Verify, 실패 시 이전 버전 유지/rollback 구현. 실제 최신 build 결과·배포 image ID는 통합환경 확인 필요.
- 최신 dev ALL-03 및 PR #92는 10-05 14:19에 #88~#91 배포됐다고 **보고**한다. 이번 작업에서 서버를 조회해 검증한 값은 아니다. 보고된 `b820b5d`와 실제 실행 image·모델·contract를 대조해야 한다.

증거 코드: **E1** 입력/interval/threshold/응답·HTTP status·시각의 요청별 기록, **E2** DB inspections/control_attempts/inspection_errors 및 late fields, **E3** history/snapshot/statistics/CSV 원본과 집합 대조, **E4** 이미지 목록·sidecar·파일 hash·preview/delete·prune 전후, **E5** 서비스 error.log·task 수명·취소·제어 호출 추적, **E6** commit/image/model/Dataset/migration/volume·Jenkins·컨테이너 상태, **E7** FE API 모드 브라우저 캡처·network 응답. 실제 증거 파일은 이번 1/4에서 만들지 않는다.

HTTP 200만 성공으로 보지 않는다. 입력 검증 실패, 정상·저신뢰·시스템 오류·저장 실패를 분리한다. 아래 CSV의 검사 행 수는 BOM·헤더를 제외한 data row 수다. DB 이력이 없으면 이미지 sidecar가 있어도 이력/통계/CSV에 행을 만들어 넣지 않는다.

## 4. #87 시간 정책과 수용 후보

| 조건 | business | 총 hard 상한 | connect |
|---|---:|---:|---:|
| 인증된 interval 1000 | 1000ms | 2000ms | 200ms |
| 인증된 interval 2000 | 2000ms | 3000ms | 200ms |
| 인증된 interval 3000 | 3000ms | 4000ms | 200ms |
| interval 누락 | 설정값, 기본 500ms | 기존 설정값, 기본 2000ms | 기본 200ms |

hard는 business 초과 후 추가 2/3/4초가 아니라 Inference task 시작부터의 총 2/3/4초다. interval은 투입 때 확정하고 공유 client timeout을 변경하지 않는다. 제한시간은 Inference 호출 구간이며 초기 DB 저장·preview·제어·최종 DB/이미지 저장을 포함한 POST 전체 완료시간과 다르다.

- 실제 deadline/ReadTimeout: 실제 HTTP 지연을 주고 재검사 판정·late task·task 취소를 관찰한다. 경계 race 대신 C에서 응답을 충분히 떨어뜨려 before business / between business and hard / after hard 세 구간으로 시험한다. 실제 task 시작 timestamp를 확보해야 하며 외부 RTT 또는 모델 `inference_time_ms`만으로 내부 deadline을 증명하지 않는다.
- 장애 주입 TIMEOUT: `_infer`가 실제 예측 task 없이 판정을 반환한다. NEXT/ALL·bin·오류·이미지·로그 검증용이며 late task 존재 증거로 쓰지 않는다. INFERENCE_ERROR 주입은 현재 `INFERENCE_HTTP_ERROR` 사유로 처리한다.
- late-result: 원래 응답·bin·control_attempts·통계 baseline을 고정하고 응답 후 DB의 `late_result_received_at/payload`와 메모리 진단을 확인한다. 정상 예측 컬럼을 채우거나 정상 통계를 증가시키면 실패다. DB 장애·초기 행 부재·재시작 때 유실은 허용한다.
- hard timeout: 예측 task의 cancellation과 manager 정리 확인, late payload 없음, 기존 재검사 유지. Backend task 취소가 원격 Inference thread의 CPU 연산 중단을 보장하는 것은 아니다.
- 1초 라인: A가 late 상태인 동안 B 정상 처리·제어·저장 완료를 관찰한다. 예측 전체를 직렬화하지 않는다. CPU·디코딩 pool 자원 경쟁은 별도 측정한다. max_late_tasks 기본 4 초과 시 추가 진단 task 취소/유실 허용 정책도 확인한다.

### 4.1 2초 라인 정량 후보 — 승인 대기

공통: 모델 warm-up은 별도 기록하고 N에서 제외. interval=2000ms 고정, concurrency=1, 변경 없는 배포·동일 모델, 실제 시연 입력, Jenkins build/test/deploy 없는 구간, 장애 주입 OFF. 저신뢰는 정상 모델 응답이므로 denominator에 포함한다. 입력 오류·연결 장애·DB 장애·배포 공백은 별도 집계하고 분자/분모에서 뺐다면 원 건수·제외 이유를 공개한다. 응답 지연 timeout과 연결 오류를 합치지 않는다.

자연 timeout 비율 = 자연 deadline/ReadTimeout으로 확정된 검사 수 / 정상 운영 유효 검사 N. 전체 요청 수·HTTP 실패·제외 건수·저신뢰 수를 함께 기록한다. timeout 요청을 임의로 다른 샘플로 대체하지 않는다.

| 후보 | N / 입력 시간 근사 | 허용 후보 | 이유 |
|---|---|---|---|
| Q1 사전 점검 | 100 / 3분20초 | 0건, 0% | 짧은 smoke 기준. 드문 timeout 안정성을 입증하기에는 표본 부족 |
| Q2 수용 후보 (권장) | 300 / 10분 | 최대 1건, 0.33% | 짧은 일정에서 반복 가능. “거의 없음”을 관찰값으로 명확히 표현 |

표의 기간은 첫 투입부터 마지막 완료까지의 정확한 wall time이 아니라 N×2초 근사다. 0건/300건이어도 장기 장애율 0%라는 증거가 아니다. Jenkins 자원 경합 구간은 별도 비교 결과로 남기며 조용한 구간 결과와 섞지 않는다. N·허용률·반복 횟수·timer 허용 오차·조회 성능의 수치 gate는 사용자 확인 후 확정한다. 승인 전 BE10-E2E-02는 정량 PASS 판정 불가다.

## 7. 입력·크기 경계 — KB-02

코드 근거: [검사 전용 _InspectionSizeRoute 및 Router 검증](../../src/api/routers/inspections.py), [전체 body 경계·stream 검증](../../tests/api/test_inspection_request_size.py), [기존 입력 검증 테스트](../../tests/api/test_inspections.py). KB-02 수정의 로컬 검증은 결과표 §8에 기록하며, 실제 wire 경계 수용시험은 아래 명세에 따라 향후 수행한다.

최신 requirements의 확정 표현과 BE-01/Backend stack은 **multipart 합계 24MiB**다. AGENTS 일부의 이미지 합계 표현, Inference의 이미지 bytes 합계 검사와 혼동하지 않는다. L=25,165,824 bytes, B=실제로 encoding한 multipart 전체 body(파일·form·boundary·header 포함), S=이미지 bytes 합계, K=inspection_id UTF-8 bytes+metadata UTF-8 bytes+UploadFile.size 합계로 정의한다.

| 조건 | 기대값 / 정확한 시험 방법 |
|---|---|
| PNG/JPEG 1장 | metadata 1개, view_index=0. 입력 계약 통과·Inference used_frame_count=1·masking. confidence에 따라 정상/저신뢰, 무조건 정상으로 기대하지 않음 |
| 12장 | metadata 12개, indexes 0..11. 실제 입력 순서 유지, used_frame_count=12 |
| 13장 | 정상 형식 metadata 13개와 함께 전송, Backend 413; Inference·제어·DB·보존 이미지 생성 0 |
| 이미지 필드 없음 | FastAPI 필수 field 422. 13장 초과와 같은 413이라고 기록하지 않음 |
| metadata JSON/개수/중복·역순 index | 422, 예측·제어·DB·보존 이미지 0. MIME PNG/JPEG 외는 415. 요청 자체가 초과 크기이면 앞선 413이 우선할 수 있으므로 한 번에 한 조건만 깨뜨림 |
| Content-Length 있음 | 정확히 encoding한 B=L-1 / L / L+1의 세 body를 사용하고 헤더=실제 B를 확인. B≤L이며 나머지 유효하면 크기 검사 통과, B>L이면 413 |
| Content-Length 없음 | 실제 HTTP chunked 전송으로 헤더 없음과 B·S·K를 증거화. K≤L이어도 B>L이면 413; B≤L이고 나머지 입력이 유효하면 크기 검사 통과 |

수정 전에는 form parsing 후 Content-Length와 K만 검사하여 Content-Length 없는 `K≤L<B` 요청에 공백이 있었다. 현재는 `/v1/inspections` 전용 APIRoute가 parsing 전에 Content-Length>L을 413으로 거부하고, 헤더 유무·유효성에 관계없이 실제 ASGI `http.request.body` chunk 길이를 누적한다. B>L이 되는 chunk는 parser에 전달하지 않고 413을 반환한다. boundary, part header, 모든 form field/file을 포함하며 HTTP 요청 줄·외부 header·chunk framing은 포함하지 않는다. 정확히 L은 허용한다. 전체 body를 재적재하지 않으며 기존 Router의 payload·1~12장·metadata·MIME 검증은 유지한다.

로컬 의존성의 Starlette parser가 파싱 중 예외 전파 시 부분 UploadFile을 닫는 동작을 검증했다(RAM 및 디스크 spool 포함). Service/Inference/제어/이미지 저장/late-result는 초과 요청에서 호출되지 않는다. 다른 endpoint에 전역 제한을 추가하지 않았다. 배포환경 의존성 및 실제 HTTP chunked 경계는 통합 수용시험에서 별도로 확인한다.

경계 fixture는 B를 실제 bytes로 계산한 정상 디코딩 PNG/JPEG로 준비하고 DM과 유효성을 확인한다. 단순 잘라내기·손상 padding으로 422를 만들고 size gate가 통과했다고 판단하지 않는다. 인위적으로 틀린 Content-Length는 HTTP 서버 자체가 먼저 거부/대기할 수 있으므로 wire acceptance boundary 근거로 사용하지 않는다. 과소·잘못된 Content-Length의 실제 byte 제한은 로컬 ASGI 시험으로 검증한다. 실제 HTTP 서버·배포환경 검증은 MO/BE 협업 사항이며 로컬 ASGI의 24MiB 경계 통과를 wire 통합 완료로 해석하지 않는다.

## 8. #55 최신 계약과 FE 의존성

저장 대상은 시스템 오류 4종(INFERENCE_DEADLINE_EXCEEDED, INFERENCE_CONNECTION_ERROR, INFERENCE_HTTP_ERROR, INFERENCE_INVALID_RESPONSE), 저신뢰 3종(LOW_CULTIVAR_CONFIDENCE, LOW_QUALITY_CONFIDENCE, LOW_BOTH_CONFIDENCE)이다. 정상·VIRTUAL_BRIX_MISSING·제어 오류만 발생한 이미지는 보존하지 않는다. 한도는 inspection 수가 아니라 **파일 장수** 100/200이고 서로 prune하지 않는다.

이미지 API는 기존 GET/DELETE `/v1/quality/fault-images`, GET `/v1/quality/previews/{id}`를 사용한다. category=SYSTEM_ERROR/LOW_CONFIDENCE, decisionReason=원 판정 사유, cultivarConfidence/qualityConfidence/appliedCultivarThreshold/appliedQualityThreshold는 0..1 또는 null. 저신뢰 errorCode=null; 시스템 timeout의 errorCode는 INFERENCE_TIMEOUT, decisionReason은 INFERENCE_DEADLINE_EXCEEDED. 이력의 저신뢰 errorCode=NONE과 이미지 null을 혼동하지 않는다.

옵션 category/inspectionId 필터(AND), 최신순 목록 최대 300, delete IDs/ack 최대 300. 미리보기·삭제는 이미지 ID, 필터·DB 추적은 inspection_id다. 기존 sidecar는 SYSTEM_ERROR로 읽고 decisionReason은 기존 error_code, 없는 confidence/threshold는 null. DB 행이 없어도 sidecar 조회 허용. snapshot/history 전체 행의 이미지 존재 여부 계산은 하지 않고 retention.images만 두 저장소 실제 장수 합산이다.

시스템 저장 시도 ERROR에는 inspection_id·decision_reason·image_storage=disabled/saved/failed·images_saved를 남긴다. saved는 당시 성공이지 영구 보존이 아니다. 저신뢰 성공은 ERROR 없음, 디스크 실패는 ERROR 가능하며 판정/제어/통계는 유지한다. 저장·prune/로그 수명이 달라 로그 ID의 이미지가 이미 만료되어도 실패로 보지 않는다.

현재 baseline FE parser(`quality-fault-images.ts`)는 100장과 non-null errorCode만 허용하고, 웹 OpenAPI 생성기도 목록/삭제 100장으로 남아 있다. PR #91은 필드 추가만 했다. **FE 의존성 FE-DEP-01**, Backend #55 결함으로 분류하지 않는다. [열린 PR #92](https://github.com/yuudong123/CQC/pull/92)는 null/300장·구분 필터·신뢰도 사유·recentCompletedJobs 연결을 수정했다고 보고하나 기준선에는 미병합이다. merge·새 기준 SHA·서버 E2E를 확인하기 전 해결 완료로 기록하지 않는다. 최신 dev ALL-03의 “생성기와 계약 JSON이 같다”는 설명은 작업본/PR 예정 상태와 baseline 불일치를 구분해 해석한다.

## 9. 시험표 읽는 방법

아래 두 표를 **동일 ID로 결합한 것이 하나의 완전한 시험 명세**다. 첫 표는 목적·입력·환경·API·검사·제어·담당·단계, 둘째 표는 DB·통계·CSV·이미지·로그·증거를 정의한다. 공통 정의는 모든 행에 적용하며 개별 override가 우선한다. 조건부 branch는 별도 결과를 남기고 하나의 PASS로 뭉치지 않는다.

- **N**: HTTP 200, COMPLETED/NORMAL, review=false, 제외=false, 정상 mapping bin·SUCCEEDED 1회.
- **L(reason)**: HTTP 200, REINSPECTION_REQUIRED/해당 저신뢰 사유, review=true, 제외=false, TEST_REINSPECTION_BIN·SUCCEEDED 1회.
- **T**: HTTP 200, REINSPECTION_REQUIRED/INFERENCE_DEADLINE_EXCEEDED, review=true, 제외=true, 재검사 bin·SUCCEEDED 1회. 이력 processing TIMEOUT/error INFERENCE_TIMEOUT.
- **E(reason)**: HTTP 200, REINSPECTION_REQUIRED/해당 오류 사유, 제외=true, 재검사 bin·SUCCEEDED 1회. 이력 processing ERROR/error INFERENCE_ERROR.
- **V**: HTTP 200, REINSPECTION_REQUIRED/VIRTUAL_BRIX_MISSING, 제외=false, 재검사 bin·SUCCEEDED 1회.
- **X**: 입력 거부, 검사·제어 미실행, DB/통계/CSV/보존 이미지 신규 0. 요청 검증 자체는 ERROR 로깅 의무 없음.
- **READ**: 조회만, 기존 검사·제어·DB 판정 불변. 로그는 조회 성공 자체의 ERROR 없음.
- **S1**: 유효 검사당 검사 1행·제어 1회 저장 SUCCEEDED, 이유·threshold·버전·UTC ms 저장. S2는 첫 거부+재검사 제어 2회.
- **M**: 전체 통계+1, 비제외 normal+1, 품종/품질·평균 추론시간 포함. M의 low/V는 reinspection+1; N은 +0. normal은 정상 bin 전용 지표가 아니라 비제외 지표다.
- **Z**: 전체+1, excluded+1, reinspection+1, 품종/품질·평균 추론시간 제외. bin 집계는 성공 제어를 기준으로 별도 확인한다.
