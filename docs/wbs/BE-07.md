# BE-07 Simulator 분리 진행 기록

- 상태: Backend와 Simulator의 프로세스 분리 코드 및 주입 자료 기반 테스트 완료. 실제 시연 데이터와 MLOps 배포 통합 검증 전이므로 BE-07 전체 완료로 표시하지 않는다.
- 범위: BE-07만. Dockerfile, Compose, Volume 설정과 BE-08/BE-09는 이번 Backend 작업 범위 밖이다.

## 현재 책임 분리

독립 앱 `src/simulator/main.py`가 Simulator 상태, revision, concurrency, faults, scope, `NEXT` 소비, 데이터 순회, runner, position 저장과 복구의 단일 소유자다. 상태는 이 프로세스 메모리에 있으며 공개 revision은 재시작 후 0에서 시작한다. `NEXT` 소비와 제어 변경은 같은 상태 lock을 사용한다. 실제 재생 위치만 별도 파일에 영속화한다. Simulator는 500ms 요청 시작 간격으로 Backend `POST /v1/inspections`에 multipart를 전송한다. 동시성은 1·2·4를 지원하며 마지막 그룹 뒤에는 처음부터 반복한다. 정지 시 새 요청 예약을 멈추고 진행 중 요청을 정리한다.

Backend에는 Simulator runner나 상태 서비스가 없다. `src/api/clients/simulator.py`가 독립 Simulator의 내부 HTTP API를 호출한다. 기존 공개 `GET /v1/quality/snapshot`은 Simulator 상태를 읽어 관제 결과에 결합한다. 기존 공개 `PUT /v1/quality/simulator`는 수정 요청을 전달하고 변경 결과를 전체 snapshot으로 반환한다. Simulator 연결이 없으면 snapshot의 Simulator 상태를 `unknown`, 제어 capability를 `false`로 표시하고 PUT은 503을 반환한다. `expectedRevision` 충돌은 공개 409 `REVISION_CONFLICT`로 변환한다. `PATCH /v1/quality/inspections/{id}/review`는 Backend에 남아 검사 검수 metadata만 갱신한다. 공개 OpenAPI 계약은 유지한다.

## 데이터와 위치

`SIMULATOR_DATASET_ROOT`에는 `index.json`, 각 그룹의 `request.json` 및 최대 12장 이미지, `demo-virtual-brix.csv`가 필요하다. 선택적 `SIMULATOR_BRIX_CSV_PATH`로 CSV 위치를 따로 주입할 수 있다. Loader는 `default_playback=true`인 12장 묶음만 index 순서로 사용하며 `request.json`의 이미지·metadata 순서를 보존한다. CSV는 원래 묶음 ID로 연결한다. 요청마다 새 UUID를 `inspection_id`로 보내고 원래 묶음 ID는 내부 인증 헤더를 통해 DB `source_reference`에 남긴다. 데이터가 없거나 유효하지 않으면 시작을 503으로 거절하고 상태를 바꾸지 않는다.

`SIMULATOR_POSITION_PATH`는 dataset root와 별개의 쓰기 가능한 영속 경로다. `next_position`은 연속으로 완료한 마지막 그룹의 다음 절대 순번이다. 완료 순서가 달라도 연속 구간만 원자 저장한다. 재시작 시 미완료 요청은 새 UUID로 재전송될 수 있다. 데이터 목록 변경이나 위치 파일 손상 시 시작을 거부한다. MLOps는 dataset을 read-only Volume, position 파일의 부모 디렉터리를 재시작 후에도 유지되는 writable Volume으로 연결해야 한다. 실제 mount 경로는 MLOps가 정한다.

## 실행과 내부 계약

- 실행 명령: `python -m src.simulator.main` (단일 Uvicorn worker)
- Simulator 내부 API: `GET /health` → `{"status":"ok"}`, `GET /state` → 현재 상태, `PUT /state` → 상태 변경. PUT의 revision 충돌은 409, dataset 시작 불가는 503이다.
- Backend→Simulator: `SIMULATOR_INTERNAL_URL`을 내부 네트워크 주소로 주입한다. 내부 제어 API는 외부에 공개하지 않는다.
- Simulator→Backend: `SIMULATOR_BACKEND_URL`로 `POST /v1/inspections`를 호출한다. `SIMULATOR_FAULT_TOKEN`은 양쪽 프로세스에 같은 값을 주입하며 Simulator 전용 헤더를 검증한다.

| 사용 프로세스 | 환경변수 | 의미 및 기본값 |
| --- | --- | --- |
| Backend | `SIMULATOR_INTERNAL_URL` | Simulator 내부 base URL. 미설정 시 adapter 비활성 |
| Backend | `SIMULATOR_INTERNAL_TIMEOUT_MS` | 내부 HTTP 제한시간, 기본 30000 |
| 양쪽 | `SIMULATOR_FAULT_TOKEN` | 동일한 비밀값. Simulator 앱에는 필수 |
| Simulator | `SIMULATOR_DATASET_ROOT` | read-only 데이터 root, 필수 |
| Simulator | `SIMULATOR_BRIX_CSV_PATH` | 선택적 CSV 경로, 기본 dataset root의 `demo-virtual-brix.csv` |
| Simulator | `SIMULATOR_POSITION_PATH` | writable 영속 위치 파일, 필수 |
| Simulator | `SIMULATOR_BACKEND_URL` | Backend 내부 base URL, 필수 |
| Simulator | `SIMULATOR_INTERVAL_MS` | 요청 시작 간격, 기본 500 |
| Simulator | `SIMULATOR_BIND_HOST` | bind 주소, 기본 `0.0.0.0` |
| Simulator | `SIMULATOR_BIND_PORT` | bind 포트, 기본 8002 |
| Simulator | `SIMULATOR_MAX_REQUEST_BYTES` | 이미지 총량 제한, 기본 25165824 |

## 장애와 검증 경계

`INFERENCE_TIMEOUT`은 시간 초과, `INFERENCE_ERROR`는 합의된 HTTP 오류로 재현한다. 연결 오류와 잘못된 응답은 검사 서비스 내부 테스트 hook으로 검증한다. `DB_ERROR`와 세 제어 오류는 해당 검사에만 주입한다. 일반 `POST /v1/inspections`는 `NEXT`를 소비하지 않는다. 공개 multipart 계약에는 Simulator 장애 필드가 없다.

주입한 임시 dataset으로 독립 앱 제어, Backend adapter, 연속 순회, 동시성 1·2·4, `NEXT` 단일 소비, position 저장·복구를 검사했다. `pytest tests/api tests/simulator -q`는 214건 통과·4건 skip(`CQC_TEST_DATABASE_URL` 미설정), 로컬 `cqc_test` MySQL 통합 4건은 별도 실행해 모두 통과했다. Ruff check와 수정 파일 format check도 통과했다. 실제 MLOps 시연 데이터는 Git에서 제외되어 현재 workspace에 없으므로 해당 자료와 배포 Volume을 이용한 실사진 통합, 별도 컨테이너 간 실제 HTTP 연결, 재시작 복구와 목표 CPU 처리량은 아직 미검증이다. 이 검증이 끝나기 전까지 BE-07을 전체 완료로 표시하지 않는다.
