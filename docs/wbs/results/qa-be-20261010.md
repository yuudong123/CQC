#### 5. SIM-04 및 E2 전용 Simulator 연결 분석

현재 E2는 Backend·Inference·MySQL로 구성되어 있으며 Simulator는 연결되지 않았습니다.

기존 일반 `cqc-simulator-1`은 별도의 Backend와 네트워크를 사용하므로 공유하지 않고 **E2 전용 Simulator를 추가하는 방안**을 검토했습니다.

- SIM-04: 실제 revision R 조회 → 설정 변경 R+1 → 이전 R 재요청 409 → 설정 유지 확인 → 복원
- SIM-05: 잘못된 입력 10종 요청 전후 실제 Simulator revision 불변 확인

두 QA 모두 검사 자동 전송은 필요하지 않습니다. `running=false` 상태의 Simulator로 검증할 수 있습니다.

**SIM-04는 아직 실행하지 않았으며, SIM-05 전체 PASS도 보류 상태입니다.**

#### 6. Simulator 자동 시작 비활성화 — 로컬 구현·테스트 및 원복 이력

정상 dataset을 연결한 Simulator가 기동 직후 검사를 전송하는 문제를 방지하기 위해 다음 3개 파일을 로컬에서 수정했습니다.

- `src/simulator/config.py`: `SIMULATOR_AUTO_START` boolean 설정 추가, 기본값 `true`
- `src/simulator/main.py`: `false`일 때 dataset·Runner를 준비하되 자동 재생만 생략
- `tests/simulator/test_app.py`: 정지 기동·설정 변경·revision·수동 시작/정지 테스트 추가

**검증 결과**
- 수정 전 테스트 35건 통과
- 수정 후 테스트 **39건 통과**
- `false` 기동 시 `running=false`, revision=0
- 자동 검사 POST **0건**
- `GET /state` 정상
- 잘못된 PUT 422·revision 불변
- 정상 PUT revision 증가
- 이전 revision 요청 409
- 수동 시작 및 정지 가능
- Ruff, `git diff --check` 통과

이 기능은 로컬에서만 구현·테스트했으며, 이후 사용자 요청에 따라 **위 3개 파일의 변경을 모두 원복했습니다. 원복 후 기존 Simulator 테스트 35건 통과, Git 작업 트리 clean 및 #117 stash 유지**를 확인했습니다. 현재 코드에 반영된 기능이나 남아 있는 미커밋 변경이 아닙니다. Commit·PR·이미지 배포·E2 적용은 하지 않았습니다. 필요성이 팀에서 합의되면 별도 코드 반영·테스트·이미지 제작이 다시 필요합니다.

#### 8. MLOps 협의 및 후속 작업

**MLOps 협의 필요 사항**

1. 자동 시작 설정은 현재 원복됐으므로 기능 필요성·코드 반영·테스트·이미지 제작 방식 및 소스 기준부터 합의
2. 해당 기능의 필요성 합의·재반영 후 E2에서만 `SIMULATOR_AUTO_START=false` 적용
3. E2 전용 Token·네트워크·position 저장소 구성
4. 정지 상태 `/health` 503을 고려한 `/state` 기반 준비 상태 확인
5. E2 Backend Simulator URL 추가에 따른 컨테이너 재생성 범위

**후속 순서**

1. 팀 합의 후 필요한 코드 재반영·테스트, 별도 승인 범위에서 Commit·PR
2. MLOps 협의 후 E2 전용 Simulator 구성
3. `running=false`, revision=0, 자동 POST 0건 확인
4. E2 DB·파일·기존 QA 증거 무결성 재확인
5. SIM-04 실제 revision 충돌 검증 및 설정 복원
6. SIM-05 실제 Simulator revision 불변 보완
7. INS-14 E1 제어 기록 확인
8. 이번 OPS-05·OPS-02는 최종 검수 후 공식 28/44에 반영. 다른 후보·부분 검증은 별도 검수 전 집계하지 않음
