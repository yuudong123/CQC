## 3. SIM-06 기존 증거와 실제 부족 범위

공식 원문은 장애별 E2 NEXT 1건 적용 및 faults=[]/revision 증가·후속 정상 처리를 요구한다. 추론 오류·시간 초과에는 각각 이미지 12장, 제어 거부에는 정상→재검사 bin 1회 대체, 무응답에는 재시도 없음·성공 bin 통계 제외, 실패에는 재시도 없음, DB_ERROR에는 이력 유실 허용·바로 다음 정상 건 저장이 적용된다.

- 신규 E1 NO_RESPONSE 11건은 검사·제어·오류의 ID 연결, 저장 제어 행 1개/attempt_no=1/NO_RESPONSE 및 저장 성공을 보완했다. **저장 행 1개는 실제 send 호출 1회/재시도 부재를 증명하지 않으며 저장 성공은 성공 bin 집계 포함을 의미하지 않는다.**
- E1 추론 오류/시간 초과 2건은 재검사 bin·SUCCEEDED·각 제어 1행을 보완했다. 기존 이미지 12장 근거는 검사별 연결 가능한 범위만 사용한다. E1로 E2 NEXT 절차를 입증하지 않는다.
- SIM-07의 기존 ALL 제어 자료는 해당 회차 상태·행의 근거로 재사용 가능하다. SIM-06의 독립 NEXT·정상 bin 대체 순서 전체를 대신하지 않는다.
- CONTROL_REJECTED·CONTROL_NO_RESPONSE·CONTROL_FAILED·DB_ERROR 부족 조건의 실제 보완 시험은 모두 **NOT EXECUTED**, 주입 0건이다. 새 제품 결함으로 확정하지 않는다.
- 팀이 E1/WSL 보완을 인정하더라도 실제 FAILED 상세·대상별 성공 bin 제외·DB_ERROR 자동 대상/직후 저장 등 남는 필수 조건은 별도 보류한다. 인정·예외 결정은 공식 수치 갱신과 분리해 기록해야 한다.

검수 결과: 제품/API/DB 스키마 수정 없음, 기본 6종 선택 호환 유지, 기존 출력/JSONL 혼합 거부, 개인 절대 경로·실제 인증값 없음. Compose는 `--project-directory`를 저장소 루트로 하고 기존 `qa-mo-sim04-sim05-20261013/isolated-compose.json` 위에 병합한다. !override 지원 Compose가 필요하며 기존 정적 확인은 Compose 5.5.1이었다. 인증 파일은 별도 비추적 경로로 관리하고 Compose 전체 렌더링의 비밀값을 출력하지 않는다.

- 회귀 결과: 92개 PASS, Ruff PASS, Python AST 문법 PASS, git diff --check PASS. 최초 샌드박스 실행은 임시 디렉터리 권한 오류로 실패했고, 승인된 별도 실행에서 새 임시 경로를 사용해 92개를 검증했다. 제품 서비스·API·DB 대역만 사용했고 Compose 검사는 config만 실행했다.
- 실제 send 횟수는 수집기의 저장 행 개수와 별도로 hook 원자료/종료 상태를 검수해야 한다. collector의 actual_send_call_count=None 및 공식 판정 미평가는 유지한다. command_id는 제품이 send 이후 생성하므로 ID/호출 번호/bin/상태/시각과 DB attempt_no를 독립 대조한다.
- 계측은 동기 파일 기록의 시간 비용이 있으므로 성능 QA에 사용하지 않는다. 계측 실패·누락·비정상 종료 시 추가 호출 부재를 확정하지 않는다.
- DB_ERROR는 --http-events와 동일 프로세스·순번 연속성/종료 상태·실행 provenance가 필요하다. legacy 이벤트를 읽을 수 있어도 연속성 근거 없이 '바로 다음'을 확정하지 않는다.
