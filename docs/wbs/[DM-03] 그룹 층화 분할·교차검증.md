# [DM-03] 그룹 층화 분할·교차검증

## 1. 작업 목적

동일 사과의 다각도 이미지가 서로 다른 데이터 세트에 섞이는 누수를 방지하면서 품종×품질 분포를 유지하는 Train·Validation·Test 분할을 만든다. 모델 구조와 입력 장수 선택의 변동성을 확인할 수 있도록 최종 Test를 제외한 5-Fold Group CV도 함께 고정한다.

## 2. 구현 내용

`src/data/split_groups.py`에 다음 기능을 구현했다.

1. 프레임 매니페스트를 `group_no` 하나당 한 행으로 축약한다.
2. 원본 Training과 Validation을 합친다.
3. `품종 × 품질` 여섯 조합별 그룹 수를 계산한다.
4. seed 42로 그룹을 섞는다.
5. 전역 70/15/15 목표와 조합별 층화를 동시에 만족하도록 그룹 수를 배분한다.
6. 최종 Test를 제외한 Train·Validation 그룹에 5-Fold를 배정한다.
7. 분할 교차와 Test의 CV 유입을 검증한다.

실행 명령:

```powershell
python -m src.data.split_groups
```

## 3. 고정 분할 결과

| 분할 | 그룹 | 그룹 비율 | 프레임 |
|---|---:|---:|---:|
| Train | 125 | 69.8324% | 17,095 |
| Validation | 27 | 15.0838% | 3,918 |
| Test | 27 | 15.0838% | 4,011 |
| 합계 | 179 | 100% | 25,024 |

그룹당 프레임 수가 8~184장으로 다르기 때문에 프레임 비율은 정확한 70/15/15가 아니다. 프레임 비율을 강제로 맞추면 그룹 층화 또는 데이터 누수가 발생할 수 있으므로 그룹 수를 기준으로 했다.

## 5. 5-Fold Group CV

최종 Test 27그룹은 어떤 CV fold에도 넣지 않았다. Train·Validation 152그룹만 품종×품질 기준으로 층화했다.

| Fold | 그룹 |
|---|---:|
| 0 | 31 |
| 1 | 31 |
| 2 | 30 |
| 3 | 30 |
| 4 | 30 |

- 모든 품종×품질 조합이 모든 fold에 존재한다.
- 조합별 fold 수 차이는 최대 1개다.
- 전체 fold 수 차이도 최대 1개다.

## 6. 주요 설계 결정과 이유

### 이미지가 아니라 `group_no`를 분할한다

동일 사과의 여러 각도 이미지가 학습과 Test에 나뉘면 모델이 새 사과의 품질이 아니라 이미 본 사과의 특징을 기억할 수 있다. 따라서 하나의 `group_no`는 반드시 한 고정 분할과 한 CV fold에만 속한다.

### 전역 목표와 조합별 층화를 함께 맞춘다

각 조합을 독립 반올림하면 전체 Validation과 Test 수가 서로 달라질 수 있다. 먼저 전체 179그룹의 목표를 125/27/27로 정하고, 각 조합의 소수점 잔여를 배분해 전역 목표까지 정확히 맞췄다.

### 결과 파일을 Git에 포함한다

데이터 원본은 Git에서 제외하지만 그룹 ID와 분할만 담은 CSV는 가볍고 재현성의 핵심이다. 모든 담당자와 CI가 같은 분할을 사용하도록 저장소에 포함한다.

## 9. 다른 파트에 전달할 계약

- 학습·평가·시연은 `configs/splits/seed-42.csv`만 분할 기준으로 사용한다.
- 원본 `Training/Validation` 폴더를 모델 분할로 다시 사용하지 않는다.
- 모델·입력 장수·신뢰도 선택에 최종 Test를 사용하지 않는다.
- 최종 Test는 모든 선택이 끝난 뒤 한 번만 평가한다.
