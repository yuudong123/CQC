# CQC WBS

## 문서 상태

역할 담당자는 확정되었다. 시작일과 종료일은 팀 일정 확정 후 입력한다.

## 역할

| 역할 코드 | 역할 | 담당자 |
|---|---|---|
| DM | 데이터 분석·모델 | 조현재 |
| FE | 프론트엔드 | 강성민 |
| BE | 백엔드 | 홍준희 |
| MO | MLOps·CI/CD | 홍유나 |

## 논리적 마일스톤

| ID | 마일스톤 | 선행 | 완료 기준 |
|---|---|---|---|
| M1 | 요구사항과 계약 확정 | 없음 | 품목·품종 범위, 모델 입출력, API 계약 합의 |
| M2 | 독립 개발 기반 구축 | M1 | 네 영역이 임시 데이터로 독립 실행 |
| M3 | 핵심 기능 완성 | M2 | 이미지 입력부터 결과 저장까지 연결 |
| M4 | 통합 검증 | M3 | 정상·오류·저신뢰 시나리오 반복 성공 |
| M5 | 두 번째 품목 확장 여부 결정 | M4 | 추가 또는 보류 결정과 근거 기록 |
| M6 | 기능 동결과 발표 준비 | M4, 필요 시 M5 | 최종 버전 반복 시연과 문서 일치 |

## 주요 의존 경로

```text
DM-1 → DM-2 → DM-3 → DM-4 → DM-5 → BE-3 → FE-3 → ALL-1
FE-1 ───────────────→ BE-1 → BE-2 → BE-4 → BE-5 ─────→ ALL-1
MO-1 → MO-2·MO-3 → MO-4 → MO-5 ─────────────────────→ ALL-1
ALL-1 → M5 확장 결정 → M6 기능 동결
```

## 일정 원칙

- M1 완료 후 M2의 네 역할은 병렬로 진행한다.
- 프론트엔드는 예시 응답, 백엔드는 임시 모델을 사용해 서로의 완료를 기다리지 않는다.
- 최종 모델 연결은 `DM-5`, 실제 화면 연동은 `BE-3` 이후 가능하다.
- 두 번째 품목 추가는 `ALL-1`의 사과 품종 2종 통합 시험이 끝난 뒤 결정한다.
