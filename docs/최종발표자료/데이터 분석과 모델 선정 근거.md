# CQC 데이터 분석과 모델 선정 근거

> 최종 발표용 설명 자료 · 2026-09-23 확인 기준
> 여기서 **외관 등급**은 AI Hub 원본의 특(L)·상(M)·보통(S), **종합등급**은 외관과 가상 당도를 조합한 프로젝트 시뮬레이션 결과다. 두 정답을 혼용하지 않는다.

## 1. 발표의 핵심 질문

우리 문제는 사진 한 장을 분류하는 것이 아니라 **컨베이어를 지나는 사과 한 개를 여러 방향에서 관찰해 품종과 외관 품질을 판정하는 것**이다. 선별 결과는 이후 가상 제어·물류 흐름에 전달한다. 그래서 학습 표본을 이미지 수로 세면 실제 문제를 잘못 정의하게 된다. 데이터 분석은 먼저 “사과가 몇 개이고, 각 사과에 어떤 사진이 있는가?”에서 시작했다.

발표에서 설명할 의사결정 흐름은 다음과 같다.

```text
원본 ZIP·JSON 실사 → 사과 단위 매니페스트와 무결성 검사
→ 같은 사과가 섞이지 않는 분할 → 대표 촬영 프레임 수·모델 구조 비교
→ v1 실패 분석 → v2 외관 모델 선정
→ 당도는 실측 부재를 명시한 시뮬레이션 → v3 종합등급 실험
```

## 2. 원본 데이터는 실제로 어떻게 생겼나

원본은 AI Hub 농산물 품질 이미지의 **부사·양광 사과** 부분이다. 이미지 ZIP 12개와 대응 라벨 ZIP 12개에서 PNG와 JSON **25,024쌍**을 확인했다. 원본 폴더 기준 Training은 21,896장·139개 사과, Validation은 3,128장·40개 사과다. 원본 PNG는 1,000×1,000 픽셀이며, JSON에는 품종·품질 등급·촬영 방향·각도·`group_no`가 기록돼 있다.

| 품종 / 원본 외관 등급 | 특 L | 상 M | 보통 S | 합계 사과 |
|---|---:|---:|---:|---:|
| 부사 | 24 | 24 | 24 | 72 |
| 양광 | 24 | 51 | 32 | 107 |
| 전체 | 48 | 75 | 56 | **179** |

**25,024는 독립 사과의 수가 아니라 촬영 프레임 수다.** `group_no`로 묶으면 물리적 사과는 179개다. 그룹당 프레임 수는 8~184장이고, 175그룹은 40장 이상이다. 따라서 프레임이 많은 사과를 여러 독립 표본으로 취급하면 표본 크기와 모델 성능을 과장하게 된다.

또한 분포가 완전히 균형적이지 않다. 예를 들어 양광·상은 51그룹으로 양광·특 24그룹보다 많다. 정확도만 보고 선택하면 적은 등급의 실패가 감춰질 수 있으므로, 각 클래스의 F1을 동일하게 반영하는 **Macro F1**을 핵심 지표로 사용했다.

### 원본 라벨을 그대로 연결하지 않고 매니페스트를 만든 이유

ZIP 파일명·JSON 필드·이미지 파일명을 전체 조사했다. `no`에는 중복 값 4,532개, `(group_no, img_no)`에는 중복 조합 5,072개가 있어 고유키로 쓸 수 없었다. 일부 JSON `identifier`도 실제 ZIP 멤버 경로와 달랐다. 따라서 같은 조합의 PNG와 JSON을 **확장자를 뺀 파일명**으로 연결하고, `원본 분할:품종:품질:파일명`을 프레임 식별자로 삼았다. 사과 식별자는 별도로 `group_no`를 유지했다.

이 과정에서 품종은 `fuji/yanggwang`, 품질은 `L/M/S` 순서로 고정했다. 매니페스트에는 원본 ZIP과 내부 파일의 상대 경로를 남겼다. 약 27.9GB 원본을 모두 압축 해제하거나 복사하는 대신, 학습 시 필요한 이미지만 읽기 위한 선택이다. **원본 라벨을 덮어쓰는 가공은 하지 않았다.**

### 이미지 품질 검사 결과

전체 25,024장을 스트리밍으로 읽어 PNG 구조·청크 CRC, ZIP CRC, 해상도, 파일 SHA-256과 이미지·JSON 짝을 검사했다. 손상·누락·해상도 불일치는 각각 0건이었다. 동일한 이미지 바이트가 서로 다른 각도 라벨로 저장된 **5쌍·10장**은 발견했다. 모두 같은 사과 그룹 안에 있어 분할 간 직접 누수는 없지만 각도 라벨 오류 후보이므로 기록하고 원본에서 자동 삭제하지 않았다. 임의 삭제는 어느 각도 라벨이 맞는지 확인하기 전에는 더 큰 오류를 만들 수 있다.

## 3. 분할의 단위는 이미지가 아니라 사과

동일 사과의 앞·뒤 사진이 각각 Train과 Test에 들어가면 모델은 처음 보는 사과에 대한 성능이 아니라 이미 본 사과의 특징을 다시 맞히게 된다. 그래서 **한 `group_no`의 모든 사진은 같은 분할과 같은 CV fold**에만 배정했다.

원본 Training/Validation 폴더를 합친 뒤, 품종×외관 등급 여섯 조합을 층화하고 seed 42로 새 분할을 고정했다.

| 용도 | 사과 그룹 | 프레임 | 사용법 |
|---|---:|---:|---|
| Train | 125 | 17,095 | 개발 학습 |
| Validation | 27 | 3,918 | 개발 검증 |
| Test | 27 | 4,011 | 모델 선택 후 평가·후속 회귀 진단 |

개발 세트 152그룹에는 31/31/30/30/30그룹의 **5-Fold Group CV**도 부여했다. 모든 품종×등급 조합이 각 fold에 있고 Test 27그룹은 CV에 포함되지 않는다. v2 개선 단계에서는 별도로 **AI Hub 원본 Training 118그룹 학습 / 원본 Validation 34그룹 검증**도 사용했다. 이는 같은 179그룹의 다른 개발 검증 방식이며, 추가 외부 데이터가 아니다.

분할 파일을 고정해 실험마다 같은 사과가 같은 역할을 하도록 했다. 프레임 비율이 정확히 70/15/15가 아닌 이유는 사과마다 프레임 수가 다르기 때문이다. 프레임 비율에 맞추려고 사과를 쪼개지 않았다.

## 4. 왜 사진을 12장으로 줄였나

사과 하나에 40장 이상이 있어도 실시간 검사에서는 모든 프레임을 모델에 넣을 필요가 있는지 실험해야 했다. 고정 선택기는 각 사과의 프레임을 **촬영 방향 → 수평각 → 수직각 → 프레임 ID** 순서로 정렬하고, 전체 목록의 처음과 끝을 포함하는 균등 간격 인덱스를 뽑는다. 4·8·12·16·40장 조건을 같은 규칙으로 만들었다. 이 규칙은 재현 가능한 **메타데이터 정렬·균등 추출**이며 사과의 상·하·전·후·좌·우 6면을 실제로 식별하는 알고리즘은 아니다.

12장보다 적은 사과는 삭제하지 않았다. 8장 그룹 1개는 실제 8장과 빈 자리 4개로 표현하고 `view_mask=False`인 자리를 특징 평균에서 제외한다. 큰 각도 집합을 가진 사과가 학습에서 더 많은 독립 사과로 계산되지도 않는다.

선택된 PNG를 읽을 때 224×224 RGB로 리사이즈하고 ImageNet 평균·표준편차로 정규화한다. 학습 중에는 수평 뒤집기와 ±8° 회전을 사용했다. 이는 메모리·연산량을 줄이고 사과 그룹 단위 입력 크기를 맞추기 위한 전처리다. 224픽셀에서 작은 결함이 사라질 위험은 남아 있어 실제 촬영 환경 검증은 별도 과제다.

### 같은 조건에서의 구조·장수 비교

처음에는 두 구조 × 다섯 입력 장수 × 다섯 fold, 총 **50회 실험**을 수행했다. `joint`는 한 이미지 특징 추출기를 품종·품질 과제가 공유하고, `separate`는 품종과 품질에 독립적인 MobileNetV3 Small 특징 추출기를 둔다. 각 사진의 특징을 먼저 추출한 뒤, 유효 사진만 사과 단위로 평균하고 두 분류 결과를 낸다.

| 구조 | 4장 | 8장 | 12장 | 16장 | 40장 |
|---|---:|---:|---:|---:|---:|
| 공동 인코더 품질 Macro F1 | 0.9294 | 0.9299 | 0.9092 | 0.9401 | 0.5493 |
| 분리 인코더 품질 Macro F1 | 0.9424 | 0.9056 | **0.9809** | 0.9480 | 0.4896 |

이 표는 **당시 각 fold에서 가장 좋은 epoch를 택한 개발 결과**다. `separate/12장`이 가장 좋아 후보가 됐지만, 이 수치만으로 최종 성능이라고 판단하지 않았다. fold마다 유리한 시점을 따로 고르면 작은 검증 세트에서는 낙관적일 수 있기 때문이다. 실제 v1 최종 Test에서 이 문제가 드러났다. 40장은 두 구조 모두 성능이 크게 낮았고 입력·연산량도 늘어 선택하지 않았다. 4장도 좋은 결과가 있었지만 사진이 사과의 모든 면을 보장하지 않아 12장으로 정했다.

## 5. v1 실패가 모델 선택을 어떻게 바꿨나

v1은 `separate/12장`, Cross Entropy, 학습률 0.001, dropout 0.2, weight decay 0.0001이었다. fold별 최고 epoch `20·15·16·19·20`의 **중앙값 19 epoch**로 개발 152그룹을 최종 학습했다. 고정 Test 27그룹에서는 품종 Macro F1 1.0000, 외관 품질 Macro F1 **0.7778**이었다. 사전 품질 목표 0.90에 미달했다.

품질 오분류 6개가 모두 **실제 상(M)**이었고, M→특(L) 4개·M→보통(S) 2개였다. 일부는 틀린 결과에도 매우 높은 신뢰도를 보여, 신뢰도 임계값만 올리는 방식으로는 해결하기 어렵다고 판단했다. 또한 M은 개발 세트에서 가장 많은 등급(63/152)이어서 단순 클래스 수 부족만으로 설명되지 않았다.

그래서 v2는 구조와 12장 입력을 유지하면서 학습 안정성을 비교했다. 학습률 0.0003, dropout 0.4, weight decay 0.0005로 조정하고 CE·Focal·순서형 손실·Focal+순서형 손실 네 후보를 비교했다. **같은 epoch에서 5-fold를 비교**하고 원본 source 검증까지 확인했다. 후보 선정에는 CV 품질 최저 fold와 source 품질 F1 중 작은 값을 강건 점수로 사용했다. 기존 Test 점수로 손실이나 epoch를 고르지 않았다.

## 6. 왜 최종 외관 모델은 v2인가

개발 비교에서 선정된 이미지 단독 설정은 `separate/12장 + Focal(gamma 2) + 4 epoch`이다. Focal은 어려운 표본에 더 무게를 두는 손실이다. Test 제외 전체 개발 152그룹으로 최종 학습했다.

| 평가 | 품종 Macro F1 | 외관 품질 Macro F1 | 해석 |
|---|---:|---:|---|
| v2 5-fold 평균 | 0.9799 | **0.8844** | 개발 세트 교차검증 |
| v2 원본 source 검증 | 1.0000 | **0.7932** | 원본 Training 118 → Validation 34 |
| v2 기존 Test 27그룹 재평가 | 1.0000 | **1.0000** | 27/27 정답, 이미 v1 평가에 쓴 Test의 회귀 진단 |

v2는 기존 Test에서 좋아졌지만 **Test 1.0000을 새로운 독립 최종 승인 성능이나 현장 성능으로 말하지 않는다.** 같은 27개 사과의 v1 오류를 이미 본 상태에서 v2 개발이 진행됐기 때문이다. 개발 CV 평균 0.8844와 source 검증 0.7932까지 함께 제시해야 평가가 균형 잡힌다. 프로젝트 시연·통합의 외관 모델로 v2를 채택했으며, 외부 농가·카메라 환경 일반화와 목표 i7-4790 CPU 수용시험은 별도 검증 사항이다.

## 7. 당도 데이터를 어떻게 다뤘나

원본 JSON에는 **사과별 실측 당도 정답이 없다.** RGB 사진에서 당도를 실제 측정했다고 말할 수 없어, 발표·정책 비교를 위한 `virtual_brix`를 **사과 한 개당 하나씩** 만들었다. 정답 품종·정답 외관 등급·split은 생성식에 넣지 않았다. 대표 사진에서 추출한 색상·붉은 면적·뷰 사이 균일도를 주요 대리 특징으로 사용하고, `group_no`와 버전으로 고정한 잡음을 더했다. 표준화 계수는 Test 제외 개발 세트에서만 맞췄다. 같은 사과는 재실행해도 같은 값을 가진다.

```text
가상 당도 = clip(14.0 + 1.5 × [0.34 × 시각 특징 점수
             + sqrt(1 - 0.34²) × 고정 잡음], 9.0, 18.0)
```

값은 소수 첫째 자리 °Brix로 저장한다. **9~18은 생성 허용 범위**이고 실제 생성된 179개 사과의 값은 **10.7~17.9, 평균 14.11**이었다. 14 이상 92개, 12~14 미만 77개, 10~12 미만 10개, 10 미만 0개다. 따라서 현재 데이터에서 ‘10 미만’ 정책 분기는 코드에는 있으나 실제 사과로 검증되지 않았다. 이 분포는 우리가 설계한 생성식의 결과이며 실제 농가의 당도 분포가 아니다.

가상 당도를 이미지와 함께 넣어 **기존 외관 등급**을 예측하는 결합 후보도 비교했다. 같은 개발 비교에서 결합 후보의 품질 5-fold 평균은 0.8592, 원본 source 검증은 0.7675로 이미지 단독 v2의 0.8844·0.7932보다 낮았다. 결합 모델의 한 source 체크포인트를 기존 Test에 재평가한 참고 점수는 0.9267(25/27)이지만, 학습 사과 수·체크포인트 선택이 v2 최종 모델과 달라 동등 비교 수치가 아니다. 이 실험은 **실제 당도 예측 능력**을 입증하지 않는다.

## 8. 종합등급 정책과 v3의 정확한 의미

유통 사례와 당도 표시 기준을 참고해 **시뮬레이션 상품성**을 별도로 정의했다. 외관 60%·가상 당도 40%는 업계에서 측정된 공통 비율이 아니라 **프로젝트가 채택한 정책 가중치**다. 후지 등 일부 품종의 당도 표시 기준인 14/12°Bx를 참고했지만, 모든 품종에 적용되는 공식 등급이나 실제 판매 등급으로 주장하지 않는다.

| 외관 등급 | 가상 당도 14 이상 | 12~14 미만 | 10~12 미만 | 10 미만 |
|---|---|---|---|---|
| 특 | 종합 특 | 종합 상 | 종합 보통 | 종합 보통 |
| 상 | 종합 상 | 종합 상 | 종합 보통 | 종합 보통 |
| 보통 | 종합 보통 | 종합 보통 | 종합 보통 | 종합 보통 |

점수는 외관 L/M/S에 100/70/40, 당도 구간에 100/70/40/0을 준 뒤 60:40으로 합산한다. 단, 특은 **외관 특·당도 14 이상·90점 이상**, 상은 **외관 상 이상·당도 12 이상·65점 이상** 조건도 충족해야 한다. 이 조건은 고당도가 외관 하자를 무제한 상쇄하는 것을 막는다. 기존 v2 외관 결과는 별도로 보존한다.

사용자 요청으로 **v3 신규 모델**은 이미지 12장 + 가상 당도·불확실성을 입력받아 이 **합성 종합등급**을 예측하도록 학습했다. v3는 원본 외관 등급을 예측하던 이전 `separate_brix` 비교 실험과 목표가 다르다. 원본 외관 라벨과 가상 당도로 종합 정답을 새로 만들되 원본 매니페스트는 수정하지 않았다. source Training 118개(L16/M61/S41)로 학습하고 source Validation 34개(L6/M15/S13)로 검증했다. 고정 Test 27개와 시연용 사진 묶음은 학습에서 제외했다.

2026-09-23 확인 결과 25 epoch 학습은 완료됐고, **최고 검증 epoch 17의 합성 종합등급 Macro F1은 0.6238**, 품종 Macro F1은 1.0000이었다. 같은 체크포인트의 기존 Test 27그룹 참고 진단은 종합등급 Macro F1 **0.7157**(20/27 정답)이었다. 동일 사과·동일 합성 종합등급 정답에서 v2 외관 예측에 60:40 규칙을 적용한 결과는 **1.0000**(27/27)이었다. 두 방법의 학습 사과 수는 각각 118개와 152개로 달라 Test 차이를 순수한 모델 구조 차이로 해석할 수 없다. 이 Test는 v1·v2에 이미 사용했으므로 새 독립 승인이나 모델 선택 근거로 사용하지 않는다. v3의 5-fold 개발 검증은 실행 중이며 완료 전 평균을 보고하지 않는다. v3의 점수는 *정책으로 만든 정답을 신경망이 얼마나 재현했는지*일 뿐 실제 당도나 유통 적합도 정확도가 아니다. 동일한 가상 값과 v2 외관 결과를 쓸 수 있다면 60:40 규칙을 직접 계산하는 방법이 결과 해석과 재현성 측면에서 더 명확하다.

## 9. 실시간 입고 시연 데이터의 역할

학습 설정으로 과거 선택됐을 가능성이 있는 사진을 보수적으로 제외하고, 남은 원본 사진 **11,304장**을 별도 `data/processed/realtime-apple-arrival-demo`에 구성했다. 12장짜리 869묶음과 1~11장 잔여 127묶음이며, 원래 물리적 사과는 **132개**다. 12장 묶음을 차례로 보내면 컨베이어에서 사과가 들어오는 흐름을 재생할 수 있다.

이 묶음은 **새 사과 869개도, 독립 Test도 아니다.** 이미 데이터셋에 있던 같은 사과의 다른 사진이다. 사진별 실제 학습 소비 로그가 없어 기록된 선택 규칙을 모든 그룹과 예정 epoch에 적용해 넓게 제외했다. 사과 ID·사진 출처·해시·각도·정답은 묶음별로 따로 보존하며 정답은 모델 입력에 전달하지 않는다. 시연 화면에서 ‘실시간 촬영’ 또는 ‘새 외부 데이터’라고 표시하지 않는다.

## 11. 발표용 설명 대본

“처음에 사진이 약 2만 5천 장이라 데이터가 충분해 보였지만, 같은 사과를 여러 각도에서 찍은 것이어서 실제 사과는 179개였습니다. 그래서 사진별로 무작위 분할하면 같은 사과가 학습과 평가에 섞이는 문제가 생깁니다. 저희는 사과 ID로 분할하고 품종·등급별 비율을 맞췄습니다. 원본 ZIP과 JSON의 연결, 손상과 중복도 전수 검사했습니다.

그다음 모델 구조 두 가지와 입력 사진 4·8·12·16·40장을 같은 교차검증에서 비교했습니다. 12장을 쓰는 품종·품질 분리 모델이 개발 성능이 가장 좋았지만, 첫 최종 Test에서는 중간 등급인 ‘상’을 여섯 개 틀렸습니다. 높은 확신의 오분류도 있어 학습률·정규화·손실과 epoch 선택 방식을 다시 검토했습니다. 이 과정을 거쳐 v2를 프로젝트 외관 모델로 선택했습니다. v2의 기존 Test 27개 정답률은 100%였지만, 이미 사용한 Test이므로 개발 검증 결과와 함께 제시하겠습니다.

당도는 원본에 실측값이 없어 이미지로 측정했다고 주장하지 않습니다. 대신 생성식을 공개한 가상 당도로 상품성 정책을 시뮬레이션했습니다. 외관 60%, 당도 40% 규칙과 그 종합등급을 학습하는 v3를 따로 실험했으며, 이 성능은 실제 맛이나 당도 판정 성능이 아닙니다. 따라서 실서비스 주장과 프로젝트 시연 결과를 구분해 보고하겠습니다.”
