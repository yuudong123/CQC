# CQC 최종 발표 대본 초안

> 표지 포함 32페이지 / 데이터 분석·모델 선정 중심

## 0. 표지 — CQC 사과 품질 판정

안녕하세요. CQC는 사과 데이터를 분석하고 모델을 비교해 품종과 외관 품질을 판정하는 프로젝트입니다. 판정 결과를 선별과 출품, 배차와 배송 관제까지 연결하는 흐름을 기획했습니다. 오늘은 데이터를 어떻게 정리하고 실험을 어떻게 바꿨는지, 그 과정에서 어떤 모델을 선택했는지를 중심으로 말씀드리겠습니다.

## 1. 문제 정의

사과의 외관을 확인하는 작업은 같은 판단을 계속 반복해야 합니다. 작업자의 숙련도와 환경에 따라 등급 판단이 달라질 수 있고, 애매한 사과를 다시 확인하는 과정도 필요합니다. 판정 이후에도 선별 결과와 출품 정보, 배송 주문을 따로 입력하면 업무가 끊어집니다. 저희는 판정 기준을 일관되게 적용하고, 한 번 생성한 결과를 다음 업무에 이어서 사용하는 흐름을 기획했습니다.

## 2. 업무 흐름 변화

기존에는 작업자가 외관을 확인하고 선별 위치를 결정한 뒤 결과를 전달했습니다. 제안한 흐름에서는 AI가 품종과 외관 등급, 신뢰도를 반환합니다. 정상 결과는 선별 목적지로 보내고 저신뢰나 오류 입력은 재검사로 보냅니다. 이 품질 결과를 검사 기록과 출품, 배송 주문에 연결해 반복 입력을 줄이는 것이 목표입니다.

## 3. 목표 서비스 흐름

먼저 사과 한 개의 다각도 이미지 12장을 입력합니다. AI 판정에 가상 당도 구간을 결합해 선별 위치를 결정하고, 관제 화면에서 검사 이력과 상태를 확인합니다. 거래·물류는 출품, 입찰, 배차, 배송 기능을 만들고 있지만 QC 결과와 어디까지 연결해 시연할지는 아직 협의 중입니다.

## 4. MVP 정의

저희가 이번에 반드시 완성할 최소 흐름은 사과 한 개를 자동으로 판정하고, 재검사 또는 선별 목적지로 분기한 뒤 결과를 기록하는 것입니다. Simulator가 사과별 사진 12장을 보내면 AI가 부사·양광 품종과 특·상·보통 외관 등급, 각각의 신뢰도를 반환합니다. 신뢰도가 낮거나 응답이 500밀리초를 넘거나 오류가 발생하면 재검사로 보내고, 정상 건은 비실측 가상 당도를 14 Brix 기준으로 나눠 12개 목적지 중 하나를 선택합니다. 작업자와 품질 관리자는 관제 화면에서 목적지와 판정 이력, 오류·통계를 확인합니다. 현재 모델과 Backend 분기, 저장·조회 API와 화면은 구현됐지만 Simulator 자동 투입과 전체 연결 시험은 남아 있습니다. 처리시간은 합성 입력에서 목표를 통과했으며 실제 사진 시험과 반복 수용시험, 외관 Macro F1 0.90 목표 확인이 필요합니다. 거래·물류 연결 범위와 시연 방식은 아직 협의 중이라 이 MVP 완료 기준에서는 보류합니다.

## 5. 데이터와 판정 단위

데이터는 이미지와 JSON 25,024쌍이며 사과는 179개입니다. 품종은 부사와 양광, 외관 품질은 특·상·보통입니다. 같은 사과를 여러 각도에서 촬영했기 때문에 group_no가 같은 이미지 묶음을 한 개의 판정 단위로 사용했습니다. 학습과 검증, 시험 데이터도 사과 단위로 나눠 같은 개체가 여러 세트에 섞이는 문제를 막았습니다.

## 6. 데이터·모델 의사결정 과정

데이터 작업은 원본을 확인하고 사과 단위로 정리하는 것부터 시작했습니다. 이후 공유·분리 구조와 사진 장수를 비교해 첫 후보를 골랐지만, v1의 Test에서 상 등급 오류가 집중됐습니다. 이 오류를 분석하면서 학습 설정과 epoch 선택 방식을 바꿨고, 이미지 단독과 가상 당도 결합도 비교했습니다. 추가 각도 증강과 종합등급 v3까지 시도한 뒤 v2를 유지했습니다. 마지막으로 시연 사진 묶음과 선별 기준을 만들고 서버컴 추론에 연결했습니다. 뒤의 페이지에서는 이 결정 과정을 단계별로 설명드리겠습니다.

## 7. 표본 규모와 등급 분포

원본 사진은 25,024장이지만 group_no로 묶으면 실제 사과는 179개입니다. 원본 Training에는 139개, Validation에는 40개가 있고, 한 사과당 사진은 8장부터 184장까지 있습니다. 부사는 등급마다 24개로 같지만 양광은 특 24개, 상 51개, 보통 32개로 차이가 있습니다. 전체에서도 상 등급이 75개로 가장 많습니다. 그래서 전체 정답률과 함께 등급별 F1을 같은 비중으로 평균하는 Macro F1을 사용했습니다. 사과 개수와 등급 분포를 먼저 확인한 것이 이후 분할과 평가 방식의 기준이 됐습니다.

## 8. 라벨 연결과 매니페스트

JSON에는 사과 ID인 group_no, 사진 번호와 품종, 등급, 촬영 각도가 들어 있습니다. 처음에는 번호 필드를 연결 키로 사용할 수 있을 것 같았지만, 실제로 확인하니 no에는 4,532개 중복 값, group_no와 img_no 조합에는 5,072개 중복 조합이 있었습니다. PNG와 JSON은 같은 조합 ZIP 안에서 확장자를 뺀 파일명으로 연결했습니다. 사진마다 분할·품종·등급·파일명을 합친 ID를 만들고, 사과 묶음은 group_no로 따로 관리했습니다. 매니페스트에는 원본 ZIP과 내부 경로를 기록해 학습할 때 필요한 사진만 읽도록 구성했습니다.

## 9. 무결성·중복 검사

25,024장을 전부 읽어 이미지와 라벨의 짝, 해상도, PNG와 ZIP의 CRC, SHA-256을 검사했습니다. 손상이나 짝 누락, 해상도 불일치는 0건이었고, 이미지 바이트가 같은 파일은 5쌍 발견했습니다. 화면의 부사 상 등급 사진 두 장도 같은 SHA-256을 가졌지만 수직각 라벨은 30도와 45도로 달랐습니다. 이런 사례는 각도 정보 점검 목록에 기록했습니다. 중복 쌍은 모두 같은 사과 그룹 안에 있었고, 원본과 점검 기록을 함께 보존했습니다.

## 10. 사과 단위 분할

같은 사과의 앞 사진을 학습에 넣고 뒤 사진을 시험에 넣으면 이미 본 사과의 특징이 평가에 섞일 수 있습니다. 그래서 같은 group_no의 모든 사진을 같은 split과 fold에 배정했습니다. 품종과 등급의 여섯 조합을 층화하고 seed 42로 Train 125개, Validation 27개, Test 27개를 고정했습니다. 개발용 152개에는 5-fold를 구성해 검증 사과를 바꿔가며 비교했습니다. 원본 출처에 따른 차이도 보기 위해 Training 118개와 Validation 34개를 사용하는 source 검증을 추가했습니다. 최종 분할에서 사과 ID 교차는 0건이었습니다.

## 11. 대표 프레임과 누락 뷰 처리

이 사진들은 같은 부사 특 등급 사과에서 실제 선택한 대표 12장입니다. 촬영 방향, 수평각, 수직각과 프레임 ID 순서로 정렬한 뒤 전체 목록에서 균등 간격으로 뽑았습니다. 이 규칙으로 4장, 8장, 12장, 16장, 40장 조건을 만들었습니다. 입력은 224×224 RGB로 맞추고 ImageNet 기준으로 정규화했으며, 학습에는 수평 뒤집기와 8도 범위 회전을 적용했습니다. 8장뿐인 사과도 포함했습니다. 실제 사진 8장과 빈 자리 4개를 넣고 view_mask를 이용해 빈 자리의 특징을 평균에서 제외했습니다.

## 12. 공유·분리 모델 비교

두 구조 모두 사진별로 MobileNetV3 Small의 특징을 추출한 뒤 유효한 뷰의 특징을 사과 단위로 평균합니다. Joint는 한 인코더를 품종과 외관이 공유하고, Separate는 품종과 외관에 각각 인코더를 둡니다. 품종과 외관이 같은 특징을 공유하는 편이 좋은지, 서로 다른 특징을 학습하는 편이 좋은지를 비교했습니다. PyTorch는 이런 다각도 입력과 마스킹, 두 구조를 직접 수정하고 실험하기 편해 사용했습니다. MobileNetV3 Small은 여러 사진을 서버컴에서 처리할 수 있도록 연산량을 고려해 선택했고 ImageNet 사전학습 특징을 활용했습니다.

## 13. 구조·입력 장수 50회 비교

공유와 분리 두 구조, 다섯 가지 입력 장수, 다섯 fold를 조합해 50회 비교했습니다. 그래프는 당시 각 fold의 최고 epoch에서 얻은 외관 Macro F1입니다. 분리 12장이 0.9809로 가장 높아 첫 후보로 선택했습니다. 사진을 40장으로 늘리면 공유와 분리 모두 성능이 크게 낮아졌고 처리량도 늘었습니다. 4장 조건도 좋은 결과가 있었지만, 더 많은 대표 시점을 활용하는 12장을 후보로 정했습니다. 다음 Test에서 개발 결과와 차이가 발생하면서 평가 시점의 선택 방식까지 다시 살펴보게 됐습니다.

## 14. v1 Test 오류 분석

첫 최종 학습은 분리 12장과 Cross Entropy를 사용했고, 152개 개발 사과로 19 epoch 학습했습니다. Test 27개에서 품종은 모두 맞혔지만 외관 Macro F1은 0.7778이었습니다. 혼동행렬을 보니 오류 6개가 모두 상 등급에 집중됐습니다. 상을 특으로 예측한 경우가 4개, 보통으로 예측한 경우가 2개였습니다. 오른쪽 사진은 실제 오류가 난 사과의 대표 이미지이고, 모델은 12장 묶음으로 판단했습니다. 오답 중 4개는 신뢰도도 96% 이상이었습니다. 개발 데이터에서 상은 가장 많은 등급이어서 학습 안정성과 등급 경계를 중심으로 개선했습니다.

## 15. Epoch 선정 방식 재검토

v1에서는 fold마다 성능이 가장 좋은 epoch를 구한 뒤 20, 15, 16, 19, 20의 중앙값인 19를 최종 학습 길이로 사용했습니다. 그런데 모든 fold를 같은 19 epoch에서 비교하니 외관 Macro F1 평균은 0.6735였습니다. fold마다 유리한 시점이 달랐던 것입니다. 14 epoch는 0.8251, 20 epoch는 0.8616으로 결과가 크게 변했습니다. 그래서 v2부터는 모든 fold의 같은 epoch를 비교하고, 평균과 함께 최저 fold와 source 검증을 반영하도록 선정 방식을 바꿨습니다.

## 16. v2 학습 안정화 실험

v2에서는 구조와 12장 입력을 유지하고 학습 조건을 바꿨습니다. 학습률은 0.001에서 0.0003으로 낮추고 dropout은 0.2에서 0.4로, weight decay는 0.0001에서 0.0005로 높였습니다. 손실은 CE, Focal, 순서형 손실, Focal과 순서형의 결합 네 가지를 비교했습니다. Focal은 어려운 표본의 영향을 키우고, 순서형 손실은 특·상·보통 사이의 등급 거리를 반영합니다. 각 후보에 5-fold와 source 검증을 적용해 24회, 당도 결합까지 포함해 48회를 실행했습니다. 공통 epoch에서 최저 fold와 source F1 중 작은 값을 강건 점수로 사용했습니다.

## 17. v2 선정 결과

선정된 설정은 이미지 단독, 분리 12장, Focal gamma 2와 4 epoch입니다. 해당 설정의 외관 Macro F1은 개발 5-fold 평균 0.8844, source 검증 0.7932였습니다. 이 설정으로 개발 사과 152개를 다시 학습했고, 기존 Test 27개를 재평가한 회귀 비교에서는 품종과 외관을 모두 맞혔습니다. 프로젝트에는 이 v2 패키지를 적용하기로 했습니다. 품종과 외관은 이미지 모델이 판단하고, 가상 당도는 별도 선별 정책에서 결합하는 구조로 정리했습니다.

## 18. 각도 재선택·증강 실험

고정 대표 사진 외에 남은 각도를 활용하는 방법도 검토했습니다. 매 epoch마다 같은 사과에서 다른 12장을 뽑아 고정 사진 의존을 줄이는 실험입니다. top과 bottom을 고려한 재선택 코드를 만들었고, fold 0과 1은 4 epoch를 완료했으며 fold 2는 3 epoch까지 진행했습니다. 이후 추가 학습을 중단하고 기존 v2를 유지하기로 했습니다. 약한 밝기와 대비 변화도 후속 후보로 정리했습니다. 사진 선택이 바뀌어도 사과 ID와 분할, fold는 그대로 유지하도록 구성했습니다.

## 19. 가상 당도 생성

가상 당도는 사과별 고정값으로 생성했습니다. 대표 사진에서 붉은 정도, 붉은 면적, 뷰 간 색상 균일도를 추출하고 개발 사과 152개를 기준으로 표준화했습니다. 이 시각 특징에 group_no와 생성 버전으로 고정한 잡음을 더했습니다. 같은 사과는 다시 실행해도 같은 값을 갖습니다. 생성된 179개 값의 범위는 10.7부터 17.9, 평균은 14.11입니다. 14 이상이 92개, 12부터 14 미만이 77개, 10부터 12 미만이 10개였습니다. 이 값을 보조 입력 실험과 선별 정책에 사용했습니다.

## 20. 가상 당도 결합 모델 비교

여기서는 이미지와 가상 당도를 함께 넣어 기존 외관 등급을 예측했습니다. 비교 결과 이미지 단독의 CV 외관 F1은 0.8844, source는 0.7932였습니다. 결합 모델은 각각 0.8592와 0.7675로 낮아졌습니다. 보조값을 추가하는 것만으로 성능이 좋아지지는 않았고, 강건 점수도 이미지 단독이 높았습니다. 따라서 외관 판정은 v2 이미지 모델을 유지하고 가상 당도는 선별값으로 따로 사용하기로 했습니다. 결합 모델의 source 최고 체크포인트를 기존 Test에 적용한 참고 진단도 기록했습니다.

## 21. 종합등급 정책 설계

외관과 가상 당도를 합친 종합등급도 실험했습니다. 외관의 특, 상, 보통에 100, 70, 40점을 주고 가상 당도 구간에도 점수를 부여한 뒤 60대 40으로 합산했습니다. 가중치만 적용하면 높은 당도가 외관을 크게 보완할 수 있어 최소 조건을 함께 뒀습니다. 종합 특은 외관 특과 당도 14 이상, 종합 상은 외관 상 이상과 당도 12 이상을 충족해야 합니다. 이렇게 계산한 정책 정답을 바탕으로 신경망이 종합등급을 학습하는 v3를 만들었습니다.

## 22. 종합등급 v3 실험

v3는 이미지 12장과 가상 당도, 불확실성을 받아 종합등급을 예측합니다. 118개를 학습하고 34개를 검증해 25 epoch 중 17 epoch를 선택했습니다. Source 종합등급 F1은 0.6238이었습니다. 같은 17 epoch로 개발 5-fold를 비교한 평균은 0.6283이고 최저 fold는 0.3592로 편차가 컸습니다. 기존 Test의 종합등급 진단은 v3가 20개, v2 외관에 규칙을 적용한 방식이 27개를 맞혔습니다. 이 결과를 정리해 통합 모델은 v2 외관 모델로 유지하고, 종합등급 학습은 별도 실험으로 남겼습니다.

## 23. 입고 시연과 모델 적용

모델 선택 이후에는 실제 입력 흐름을 재생할 자료를 만들었습니다. 기록된 학습 선택 규칙으로 13,720장을 제외하고 남은 11,304장을 시연용으로 구성했습니다. 원본 사과 132개에서 12장 완성 묶음 869개와 잔여 묶음 127개를 만들었습니다. 묶음을 순서대로 보내고 v2가 품종과 외관, 신뢰도를 반환하는 흐름입니다. 선별 목적지는 품종 2종, 외관 3등급, 가상 당도 2구간을 조합한 12개로 정했습니다. 서버컴의 Backend와 Inference HTTP 시험을 진행했고, 이후 Docker 이미지 빌드에 모델 패키지를 포함했습니다.

## 24. 최종 선별 정책

최종 선별 기준은 v2의 품종과 외관 등급, 가상 당도 14 미만과 이상입니다. 세 기준을 조합해 정상 목적지 12개를 만들었습니다. Backend는 신뢰도와 오류, 제한시간을 확인하고 정상 목적지 또는 재검사 bin을 결정합니다. 데이터 분석과 모델 실험에서 고른 판정 방식을 실제 선별 흐름에 적용하는 단계입니다.

## 25. 시스템 아키텍처

시스템은 품질 검사·선별 영역과 거래·물류 영역으로 나뉩니다. 입력 시뮬레이터가 이미지 묶음과 가상 당도를 보내면 품질 검사에서 판정 결과를 확인하고 목적지를 결정합니다. 검사 기록은 관제 화면에 표시하고, 품종과 등급, 수량은 출품 정보로 연결할 계획입니다. 낙찰 이후에는 배송 주문을 기준으로 차량을 배정합니다. 그림의 실선은 구현된 연결, 점선은 연결 예정인 부분입니다.

## 26. 소프트웨어 아키텍처

품질 관제와 입찰, 배송 관제는 공통 Next.js 웹에서 제공합니다. QC Backend는 Inference API에 이미지를 보내고, 반환받은 품종과 외관 등급, 신뢰도로 선별 정책을 적용합니다. 검사 이력은 MySQL, 출품과 주문, 차량과 노선은 물류 API와 MongoDB가 담당합니다. 입찰은 WebSocket으로 갱신하고 차량 상태는 2초마다 조회합니다. QC 결과를 물류 출품으로 넘기는 연결 작업을 진행할 예정입니다.

## 27. 실행·배포 아키텍처

사용자는 브라우저로 웹에 접속하고 프로그램은 서버컴의 Docker Compose에서 실행하는 구조입니다. QC 5개와 물류 3개, 총 8개 실행 단위로 구성했습니다. Inference 이미지에는 모델 파일을 함께 넣고, MySQL과 MongoDB는 데이터 볼륨을 사용합니다. Jenkins는 저장소 코드를 받아 설정 검사와 이미지 빌드, 서비스 기동 및 상태 확인을 수행하도록 구성했습니다. Frontend와 Simulator의 루트 배포 연결은 후속 작업입니다.

## 28. 최종 시연 구성

확정한 시연 흐름은 사과 입력, 판정, 정상 선별과 재검사 분기, 관제까지입니다. 12개 정상 목적지와 재검사 목적지, 판정 이력과 상태를 확인하는 과정을 보여드리겠습니다. 거래·물류 기능의 연결 범위와 시연 순서는 팀 협의 후 정리하겠습니다.
