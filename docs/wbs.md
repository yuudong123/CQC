# CQC WBS

## 1. 문서 기준

- 프로젝트 기간: **2026-09-16~2026-10-16**
- MVP: 부사·양광의 품종과 특·상·보통 품질 판정
- 처리 목표: 500ms 간격 입력과 초당 사과 그룹 2개. Inference 요청 전송부터 응답 전체 수신까지 500ms, 가상 제어 100ms
- 배포 환경: Intel Core i7-4790, RAM 16GB, CPU Docker 환경
- 기능 동결: **2026-10-13**. 이후 치명적 오류만 수정한다.
- 두 번째 농산물 품목은 이번 WBS의 필수 범위에서 제외한다.

## 7. 병렬 진행과 변경 원칙

- M1 계약 후 네 파트는 mock과 고정 계약으로 병렬 개발한다.
- 프론트엔드는 실제 API를 기다리지 않고 mock 응답으로 시작한다.
- 백엔드는 최종 모델을 기다리지 않고 mock inference로 상태·DB·제어를 구현한다.
- MLOps는 각 파트의 최소 실행 명령이 생기는 즉시 CI와 Compose에 연결한다.
- 대시보드 차트 종류는 강사 확인 후 FE-05 범위에서 조정하되 API 계약을 불필요하게 바꾸지 않는다.
- 모델 파일과 체크포인트는 Git에서 제외하고 배포 환경에 별도로 제공한다.
- 10월 13일 이후에는 발표를 막는 치명적 오류만 수정한다.
