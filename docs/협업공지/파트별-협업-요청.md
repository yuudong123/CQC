# 조현재 협업 필요 사항

> 기존 공지와 계약을 반복하지 않고, 조현재가 각 담당자와 실제로 주고받아야 할 내용만 정리한다.

## 강성민 — 프론트엔드

### 내가 전달할 것

- 화면에 표시할 품종·품질 코드와 confidence 예시
- 모델 버전, 추론시간, 승인 여부 등 관리자 화면에 필요한 모델 정보
- 저신뢰·오분류 사례의 화면 확인용 샘플 결과

### 내가 받을 것

- 실제 화면에서 모델 결과가 어떻게 표시되는지 캡처 또는 실행 화면
- 품종·품질 confidence가 각각 표시되는지 확인 결과
- 프론트에서 추가로 필요한 모델 응답 필드 목록

### 교류 완료 기준

- 샘플 응답 한 건으로 정상·저신뢰 화면을 확인하고, 모델 출력 필드의 추가·변경 필요 여부를 서로 확정한다.

## 홍준희 — 백엔드·DB

### 내가 전달할 것

- 실행 가능한 inference API와 OpenAPI 파일
- 모델 입력 장수·형식·용량 제한
- 모델 출력 필드, 신뢰도 기준, 모델 버전
- 연동 검증용 모델 패키지와 체크섬

### 내가 받을 것

- Backend가 inference에 보내는 실제 요청 예시
- Backend가 저장·전달하는 모델 응답 필드 목록
- timeout, 입력 오류, inference 오류 처리 결과
- 실제 연동 중 발견된 요청·응답 계약 불일치 사항

### 교류 완료 기준

- Backend에서 실제 이미지 그룹을 inference로 보내고 응답을 받아 DB·프론트 전달 직전 형태까지 확인한다.
- 계약 불일치가 있으면 어느 쪽을 수정할지 합의하고 OpenAPI에 반영한다.

## 홍유나 — MLOps·CI/CD

### 내가 전달할 것

- 모델 파일·manifest·SHA-256과 모델 버전
- inference 실행 명령, 의존성, healthcheck 경로
- CPU 성능시험 명령과 측정할 지표
- 현재 모델이 연동 검증용이며 품질 승인 모델은 아니라는 상태

### 내가 받을 것

- 배포 환경의 모델 마운트 경로와 실제 로딩 확인 결과
- i7-4790에서 측정한 평균·최대·p95, 처리량 결과
- healthcheck와 체크섬 검증 결과
- 배포 실패 로그 또는 실행환경 차이

### 교류 완료 기준

- 같은 모델 버전과 체크섬이 배포 환경에서 로딩된다.
- 목표 CPU의 성능시험 결과를 받아 모델 카드와 최종 선정 근거에 반영한다.

## 팀 전체

### 내가 요청할 것

- 개선 모델을 검증할 신규 독립 holdout 데이터 확보 여부와 방법 결정
- 모델 품질 기준 미달 상태에서 기능 통합을 계속 진행할지 확인
- 물류 플랫폼을 최종 발표 범위에 포함할지 결정

### 내가 공유할 것

- v2 학습 결과
- v2 기준 미달 시 `data/sampling` 후속 실험 결과
- 새 모델의 승인 여부, 버전, 체크섬, 성능과 한계

## 실제 연락 순서

1. 홍준희에게 inference 연동 요청 및 실제 요청·응답 확인
2. 홍유나에게 동일 모델 패키지 배포와 i7-4790 수용시험 요청
3. 강성민에게 Backend를 거친 실제 응답으로 화면 표시 확인 요청
4. 세 결과를 모아 팀 전체에 모델 상태와 통합 가능 여부 공유
