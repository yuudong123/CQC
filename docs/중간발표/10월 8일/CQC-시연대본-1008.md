## 2. 실제 서버 품질 관제 (약 4분)

지난번에는 목업 화면이었는데, 지금은 학원 서버에서 Simulator가 사과를 넣고, Backend가 Inference에 판정을 맡기고, 결과를 MySQL에 저장한 것을 그대로 보여주는 화면입니다.
**[동작]** 상단 **서버 관제** 배지 가리키기

### 2-1. 처리 중 사과 (약 40초)

왼쪽 위는 지금 처리 중인 사과입니다. 같은 사과를 여러 각도에서 찍은 12장이 한 묶음으로 들어오고, 모델은 12장을 합쳐서 품종 하나, 등급 하나를 냅니다. 처리가 끝나도 다음 사과가 들어올 때까지는 사진과 판정 결과를 남겨 둬서, 화면이 비거나 흔들리지 않습니다.
**[동작]** **처리 중 사과** 패널의 12장 사진 가리키기 → 아래 "처리 완료 · 다음 사과 대기"와 판정 결과가 뜨면 같이 가리키기

### 2-2. 재검사·오류 사과 (약 1분)

정상 판정은 실시간으로 볼 필요가 적다는 의견을 반영해서, 왼쪽 아래에는 다시 봐야 하는 사과만 남겼습니다. 품종이나 품질 신뢰도가 기준에 못 미치면 재검사, 추론 시간 초과처럼 시스템 문제면 오류로 나뉘고, 사유와 기준에 못 미친 신뢰도를 같이 보여줍니다. 기준은 품종 0.50, 품질 0.60이고, 신뢰도 보정으로 재검사 비율을 23.7%에서 16.4%로 줄였습니다.
**[동작]** **재검사·오류 사과** 패널 → **재검사** / **오류** 버튼 한 번씩 눌러 보이기 → **전체**로 돌려놓기

멘토링 의견대로 재검사 사과 사진도 원인 확인용으로 보관합니다. 검수 이미지 창에서 시스템 오류와 저신뢰 재검사를 나눠 보고, 어느 신뢰도가 기준에 얼마나 못 미쳤는지 같이 볼 수 있습니다.
**[동작]** 상단 **검수 이미지 n장** → 구분 **저신뢰 재검사** 선택 → 사유 칸의 "품질 xx% < 60.0%" 가리키기 → 한 행 **미리보기** → 창 닫기

### 2-3. 처리 현황과 라인 속도 (약 1분 30초)

처리 현황은 최근 5분 처리량을 선그래프로 그리고, 설정한 라인 속도를 점선으로 겹쳤습니다. 선이 점선을 따라가면 라인이 속도를 맞추고 있는 거고, 아래로 내려가면 못 따라가고 있다는 뜻입니다. 재검사·오류가 난 시점은 점으로 찍힙니다.
**[동작]** **처리 현황** 그래프의 선과 점선 가리키기

실제 선별기가 레인당 초당 1~3개를 처리해서, 라인 속도를 관제 화면에서 바꿀 수 있게 했습니다.
**[동작]** 상단 **시연 설정** → 라인 속도 **3초마다 1묶음** 선택 → 창 닫기 → 그래프 점선이 내려가는 것 보여주기

추론 제한시간도 라인 속도에 맞춰 바뀝니다. 처음에는 500밀리초로 고정했는데, 사과 사이 여유가 2초인데도 0.5초만 넘으면 재검사로 빠졌습니다. 지금은 다음 사과가 오기 전까지, 즉 라인 속도만큼 기다립니다.

저희 서버에서는 2초 간격이 안정적이라 다시 2초로 돌려놓겠습니다.
**[동작]** **시연 설정** → 라인 속도 **2초마다 1묶음** → 창 닫기

### 2-4. 장애 시연 (선택, 시간 남으면 30초)

모델이 늦거나 DB가 끊기는 상황도 시연할 수 있습니다. 추론 시간 초과를 다음 1건에만 걸어 보겠습니다.
**[동작]** **시연 설정** → 적용 범위 **다음 1건** → **추론 시간 초과** 체크 → 창 닫기

시간 초과가 난 사과는 재검사로 빠지고, 재검사·오류 목록에 사유가 뜹니다. 사진은 원인을 확인할 수 있게 서버에 보관합니다.
**[동작]** **재검사·오류 사과**에 새로 생긴 "추론 시간 초과" 줄 → 상단 **검수 이미지 n장** 버튼 가리키기

> 서버가 장애 설정을 허용하지 않으면(체크박스 비활성) 이 순서는 건너뛴다. 끝나면 **장애 토글 모두 해제**.

### 2-5. 이력·통계 (약 30초)

검사 이력은 MySQL에 쌓이고 필터 결과 전체를 CSV로 내려받을 수 있습니다. 기간 통계는 지금 1~30분 범위와 오늘 집계까지 있고, 일·주·월 추세는 확장 방향으로 정리해 두었습니다.
**[동작]** 상단 **검사 이력** 열어 보이고 닫기 → **기간 통계** 열어 보이고 닫기
