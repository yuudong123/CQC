## 1. 들어가기 앞서: MVP와 아키텍처 (약 3분)

**[말]** 시연 전에 먼저 말씀드릴 게 있습니다. 지난 멘토링에서 MVP 구성을 명확히 했으면 좋겠다는 피드백을 받았습니다. 그래서 MVP를 정의하는 페이지를 따로 만들었고, 아키텍처도 시스템·소프트웨어·실행 배포 세 가지로 나눠서 각각 페이지로 정리했습니다. 이 네 페이지를 짧게 보여드리고 시연으로 넘어가겠습니다.

### 1-1. MVP 정의 (5쪽, 약 1분)

**[말]** 저희 MVP는 "사과 1개를 자동으로 판정하고, 재검사로 나누고, 가상으로 선별하고, 이력으로 확인하는 것"입니다.
**[동작]** 위쪽 다섯 칸을 왼쪽부터 차례로 가리키기

**[말]** 순서대로 보면, 같은 사과 사진 12장이 들어오고, 품종과 외관 등급을 각각 신뢰도와 함께 판정합니다. 신뢰도가 낮거나 오류가 나거나 응답이 500ms를 넘으면 재검사로 보냅니다. 정상이면 품종 2 × 등급 3 × 가상 당도 2구간으로 12개 선별함 중 하나로 가고, 재검사함까지 해서 12+1개입니다. 마지막으로 결과를 MySQL에 저장하고 관제 화면에서 봅니다.

**[말]** 아래 표는 MVP 완료 기준과 오늘 기준 상태입니다. 자동 투입부터 판정·재검사 분기까지는 학원 서버에서 실제로 돌고 있습니다. 다만 목표였던 초당 2건은 서버에서 재보니 0.63건이라, 시연 입력 간격을 2초로 맞췄습니다. 모델 정확도 기준 0.90도 아직 미달이라 그대로 적어 두었습니다.
**[동작]** 아래 **완료 판단 기준** 표에서 3번째 줄(500ms)과 마지막 줄(Macro F1) 가리키기

**[말]** 거래·물류 연결은 이 페이지에서 "협의 중"으로 남겨 뒀습니다. 이건 시연 마지막에 의견을 여쭙겠습니다.
**[동작]** 표 위 회색 문구 "거래·물류 연결: 포함 범위·시연 방식 협의 중" 가리키기

### 1-2. 시스템 아키텍처 (26쪽, 약 40초)

**[동작]** `26` Enter
**[말]** 시스템 아키텍처는 "무엇이 무엇에 데이터를 넘기는지"를 역할 단위로 그린 그림입니다. 왼쪽이 품질 검사·선별 영역입니다. 입력 시뮬레이터가 사진 12장과 가상 당도를 넘기면, 품질 검사가 판정하고, 가상 선별이 12개 정상함 또는 재검사함을 정합니다. 그 결과는 관제·이력·통계로 갑니다.
**[동작]** 왼쪽 상자들을 화살표 순서대로 따라가며 가리키기

**[말]** 오른쪽이 거래·물류 영역입니다. 검사 결과로 출품·입찰·낙찰을 하고, 그 주문으로 자동 배차와 배송 관제를 합니다. 실선은 구현된 연결, 점선은 연결 예정입니다.
**[동작]** 오른쪽 상자와 아래 "실선: 구현 / 점선: 연결 예정" 범례 가리키기

### 1-3. 소프트웨어 아키텍처 (27쪽, 약 40초)

**[동작]** `27` Enter
**[말]** 소프트웨어 아키텍처는 실제 프로그램 단위입니다. 화면은 Next.js 웹 하나로 품질 관제, 검사 이력, 출품·입찰, 배송 관제를 다 보여줍니다.
**[동작]** 맨 위 **공통 웹** 상자 가리키기

**[말]** 품질 쪽은 FastAPI Backend가 검사 요청을 받아서 Inference API에 사진을 넘기고, 선별 정책을 적용해서 MySQL에 저장합니다. 모델은 PyTorch MobileNetV3 Small입니다. 물류 쪽은 별도 FastAPI가 입찰·배차를 맡고 MongoDB에 저장합니다. 그래서 품질 기록은 MySQL, 거래·배송 기록은 MongoDB로 나뉩니다.
**[동작]** 왼쪽 QC Backend → Inference → MySQL, 오른쪽 물류 API → MongoDB 순서로 가리키기

### 1-4. 실행·배포 아키텍처 (28쪽, 약 40초)

**[동작]** `28` Enter
**[말]** 실행·배포 아키텍처는 이게 어디서 어떻게 돌아가는지입니다. Git에 올리면 Jenkins가 설정 검사, 이미지 빌드, 기동 확인을 하고 학원 서버컴에 Docker Compose로 띄웁니다.
**[동작]** 위쪽 Git 저장소 → Jenkins → 서버컴 화살표 따라가기

**[동작]** 아래 줄 backend·inference·mysql·simulator 상자 가리키고, 점선 **frontend** 상자 가리키기

**[말]** 그럼 실제 화면으로 넘어가겠습니다.

**[말]** 판정이 끝나면 품종, 등급, 신뢰도와 함께 어느 선별함으로 갈지가 정해집니다. 아까 MVP에서 말씀드린 12개 정상함 중 하나입니다.
**[동작]** **최근 판정** 표에서 한 줄 가리키며 "부사 / 특 → DEMO_BIN_xx" 읽기

**[말]** 신뢰도가 기준보다 낮으면 자동으로 보내지 않고 재검사로 돌립니다. 기준은 품종 0.50, 품질 0.60인데, 신뢰도 보정을 해서 재검사 비율을 23.7%에서 16.4%로 줄였습니다.
**[동작]** 표에서 노란 **검수** 배지가 있는 줄 가리키기 (없으면 잠깐 기다렸다가)
