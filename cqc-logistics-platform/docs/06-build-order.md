# 바이브코딩 작업 순서

각 단계는 화면만 또는 API만 따로 만들지 않고 작은 전체 흐름으로 끝낸다.

## 0. 뼈대

- Next.js, FastAPI, MongoDB, Compose 생성
- health check와 seed 명령
- 공통 상태 enum, 시간·금액·GeoJSON 타입

완료: 새 환경에서 한 명령으로 세 서비스가 뜨고 seed 데이터를 조회한다.

## 1. CQC → 출품

- `cqc_results`, `lots` 저장
- 농가 CQC 결과 목록과 출품 폼
- 추천가는 고정 규칙 mock

완료: CQC 샘플 하나로 공개 출품을 만든다.

## 2. 입찰 → 낙찰

- 입찰 검증, 최고가, 종료 처리
- 구매자 마켓 화면
- 경매 WebSocket

완료: 브라우저 두 개에서 입찰가가 동시에 갱신되고 주문이 한 건만 생긴다.

## 3. 낙찰 → 자동배차

- 차량 seed와 2dsphere 인덱스
- 용량·거리 기반 후보 계산
- 주문, 노선, 차량의 원자적 연결

완료: 적재 가능한 가장 유리한 차량이 선택되고 픽업·하차 경유지가 생긴다.

## 4. 관제와 GPS

- 차량 위치 시뮬레이터
- 2초 위치 Polling
- 지도 또는 좌표 기반 fallback 관제

완료: 차량 마커가 노선을 따라 이동하고 도착 상태가 바뀐다.

현재 상태: API 차량 단계 이동과 도착 상태 전이까지 구현·검증 완료.

## 5. 상·하차 게이트

- 도착 반경 판정
- 상차·하차 확인 버튼
- 적재량·주문·경유지 상태 갱신

완료: 버튼을 누르기 전 차량이 다음 단계로 움직이지 않는다.

현재 상태: 상차·하차 완료 API와 적재량·주문·노선 상태 갱신까지 구현·검증 완료.

## 6. 동적 경유지

- 운행 차량도 후보에 포함
- 유휴 후보가 없을 때 운행 후보를 거리로 선택하고 첫 미완료 하차 앞에 삽입
- 노선 version 충돌 처리

완료: 신규 주문이 기존 운행에 합류하고 픽업보다 하차가 앞서지 않는다.

현재 상태: 유휴 차량이 없을 때 잔여 적재량이 있는 운행 차량의 첫 미완료 하차 앞에 새 픽업·하차를 삽입한다.

## 7. 고장과 대체배차

- 고장 이벤트와 차량 운행 제외
- 미완료 주문 재배차
- 이벤트·알림 패널

완료: 고장 차량이 멈추고 대체 차량이 새 노선을 받는다.

현재 상태: `/fleets/{fleetId}/breakdown`에서 고장 차량·취소 노선·대체 차량·새 노선을 함께 반환한다.

## 8. 발표 마감

- 데모 제어 화면
- 로딩·빈 상태·오류 상태
- seed 초기화와 5분 데모 스크립트
- 핵심 API 통합 테스트

현재 상태: `/control`에서 차량 목록 2초 폴링, 위치 1스텝 이동, 고장·대체배차 버튼을 연결했다.
`/control/overview`와 `/control/seed-reset`으로 발표용 요약·알림·초기화 흐름도 연결했다.
